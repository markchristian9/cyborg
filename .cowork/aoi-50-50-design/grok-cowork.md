## 1. 결론 요약

**이 프로젝트에서 AOI는 구독 SQL로 “가까운 50”을 고르는 기능이 아니라, (①) 종류별 밀도에 맞춘 청크 등식 구독으로 수신 면적을 자르고 (②) 클라이언트에서 표시·처리 상한 50+50을 강제하는 두 겹으로만 성립한다.**  
균등 동접 1,000·몹 평균 ≈7,500 전제에서 PC 50 역산 \(C_{pc}\approx 75\), 몹 50 역산 \(C_{mob}\approx 27\)이며 **동일 면적 창으로 둘을 동시에 평균 50에 맞출 수 없다**(밀도비 ≈7.5). 구현은 (A) 종류별 청크 한 변 분리(권장, OR 9+9) 또는 (B) 동일 \(C=32\)에 PC 7×7·몹 3×3 창 분리(OR 폭증) 중 하나다.  
**청크만으로는 50 상한을 보장하지 못한다**(안전지대 집결·레벨 링 피크). 현행은 `SELECT *` 전체 구독이라 목표가 성립하지 않는다. 전원 이동·현재 행 크기 가정에서 **클라당 수신 부하는 PC 쪽이 더 크고**, 세로 분할·2Hz·정지 몹 미기록 후에는 **몹 쓰기가 역전할 수 있다.**

## 3. 상세 분석

### 3.1 이 프로젝트 기준 “AOI를 설정한다”는 뜻

구독 방언은 `SELECT *`·등식/비교 위주이며 **`ORDER BY`/`LIMIT`/거리 산술이 없다**(`GAME-SERVER.md:109-122`). 따라서 “가까운 50 PC·50 몹”을 SQL 한 줄로 쓸 수 없다.

| 겹 | 역할 | 현재 코드 |
|---|---|---|
| **① 면적(구독)** | `chunk = c0 OR …`(보통 3×3)로 **수신 행 집합** 축소 | 없음 — `kWorldSubscriptions` 전체 표 |
| **② 상한(클라)** | 거리 정렬 후 최대 50만 그리기/처리 | 몹: r=60·max **140** / 원격 PC: **무제한** |

**청크 한 변 \(C\)는 원하는 평균 개수 \(A\)와 밀도 \(\rho\), 창 칸 수 \(K^{2}\)에서 역산**한다(구 문서 AOI100과 동일 방법, 목표만 50).

\[
K^{2}\,C^{2}\,\rho = A
\quad\Rightarrow\quad
C=\sqrt{A/(K^{2}\rho)}
\quad(K=3\Rightarrow 9C^{2}\rho=A)
\]

- **역산 입력:** \(A\)(평균 목표), \(\rho\), \(K\)(기본 3).  
- **역산하지 않는 것:** 카메라 픽셀, 어그로 9, 기존 AI `CHUNK_TILES=32` — 목적·수식이 다름(`world.rs:655-659`, `GAME-SERVER.md:360-361`).

### 3.2 \(C_{pc}\)·\(C_{mob}\) 각각 — 단일 \(C\)로 동시 만족 불가

**전제(균등·평균):**  
- 면적 \(1000^{2}\)(`world.rs:51`), \(N=1000\) → \(\rho_{pc}=0.001\).  
- \(M\approx 200\times 3\times 12.5=7500\) → \(\rho_{m}=0.0075\) (`CLUSTER_*`·용량 주석 `world.rs:87-108`).

| 목표 | \(K=3\) 식 | \(C\) | 9칸 한 변 | 검산 평균 | 보행 체류(3.6 t/s) |
|---|---|---:|---:|---:|---:|
| PC 50 | \(9C^{2}\times0.001=50\) | **≈74.5 → 75** | 225 | 50.6 | ≈20.8 s |
| 몹 50(균등) | \(9C^{2}\times0.0075=50\) | **≈27.2 → 27** | 81 | 49.3 | ≈7.5 s |
| (참고) AI | 어그로 여유 | **32** | 96 | 몹≈69 | ≈8.9 s |
| (구 AOI100) | PC 100 | **104** | 312 | ≈97 | ≈29 s |

검산: AOI100의 \(C=104\)에 \(\sqrt{50/100}\) → \(≈73.5\approx 75\) — 문서 방법과 정합(`GAME-SERVER.md:345-356`).

**한 크기로 둘 다?**  
- \(C=75\): 균등 몹 \(9\times75^{2}\times0.0075\approx 380\) (**목표의 ~7.6배**).  
- \(C=27\): 균등 PC \(≈6.6\) (**목표의 ~13%**).  
→ **평균 50을 동시에 맞추는 단일 \(C\)는 없다.**

**구현 선택지(둘 다 “면적 역산”을 만족):**

| 안 | 내용 | OR 개수 | 비고 |
|---|---|---:|---|
| **A (권장)** | \(C_{pc}=75\), \(C_{mob}=27\), 각 3×3 | 9+9 | 컬럼·상수 2계열 |
| **B** | 공통 \(C=32\), PC **7×7**, 몹 3×3 | 49+9 | \(7^{2}\times1024\times0.001≈50.2\); 몹 3×3≈69(약간 초과) |

1차가 A만 단정한 것은 과하다. 다만 **B는 PC OR 49개**로 구독 문자열·전환 비용이 커 A가 실무상 우세하다.  
기존 `Monster.chunk`(집·32)는 roam 26 안 추적용이지 **현재 화면 구독용이 아니다**(`world.rs:414-418, 150-152`).

### 3.3 군집 배치가 청크 설계에 주는 영향

- 클러스터 내부 밀도 ≈ \(12.5/(\pi 9^{2})≈0.049\) → 전역 균등 0.0075의 **~6.5배** (`CLUSTER_RADIUS=9`).  
- 직경 ≈18 무리는 \(C≥≈20\)이면 한 청크·3×3에 통째로 들어와 **사냥터 단위는 유지**된다.  
- 레벨 링: `band≈(outer-inner)/200≈2.3` 타일(`world.rs:872-880`). 플레이어 주변 한 변 81(\(C=27\))이면 **여러 레벨 링이 한 창에 겹칠 수 있어** 균등 역산 50을 **피크가 크게 웃돈다**.  
- **평균 용량 계획 = 균등 역산 / 보장 = 표시 상한 + (원하면) 집결 설계 회피.** \(C\)만으로 “항상 50”은 거짓이다.

### 3.4 카메라 뷰포트 vs AOI 청크

- 줌: `zoom = (screenH/760).clamp(0.55,1.6) * zoomScale`, `zoomScale∈[0.5,2.0]` (`action_rpg_game.dart:299-331`).  
- 아이소: `kTileWidth=128`, `kTileHeight=64` (`iso.dart:6-9`). 화면 네 모서리 → 그리드 AABB(`visibleGridBounds`, 1010-1039).  
- **대략적 span(AABB 한 변):** \(\approx W_{world}/128 + H_{world}/64\). 세로를 ~760px 분량으로 맞추는 설계상, 대표 폰/태블릿·기본 줌에서 **대략 12~22 타일**, 줌아웃 0.5에서 **~2배(≈25~45)**. (정밀 값은 해상도별로 `visibleGridBounds` 실측.)  
- 지형 스트리밍 청크 32(`iso.dart:47`) ≠ 구독 청크.

| 창 | 한 변 | 화면(≈15~22) 대비 | 몹 스트림 r=60 대비 |
|---|---:|---|---|
| 뷰포트 | ~12–45 | 기준 | 스트림이 더 넓음 |
| 9×\(C=27\) | 81 | **과잉(~2–5×)** | 중심→창 모서리 ~57; r=60은 **가장자리에서 데이터 없는 필터** 가능 |
| 9×\(C=75\)(PC) | 225 | **대폭 과잉(~10×)** | 재구독·평균 인원용 여유 |

**판단:** 화면만 보면 9청크(특히 PC 75)는 **시각적으로 과잉**이다. 목적은 팝인 방지·재구독 빈도·등식 SQL 표현이다. 목표 표시 50이면 몹 스트림 반경·`_maxActiveMonsters`를 **구독 창과 정합**(예: r≈40–45, max 50)시키는 편이 일관된다.

### 3.5 몬스터 50 + PC 50 트래픽 (비대칭)

갱신 = **delete+insert 두 행 이미지**(`shared_types.dart:59-68`).  
행 크기: 필드 합 고정부 WP≈133B + 문자열 → **문서 기준 ≈180B / 몹 ≈90B**(`GAME-SERVER.md:187`); 짧은 이름 가정 시 1차의 ~161/79도 같은 자릿수. 아래는 **180/90·전원 이동·\(A=50\)** 최악 자리수.

| 소스 | 논리 갱신/s | 행 이미지/s | ≈KB/s·클라 |
|---|---:|---:|---:|
| PC 5Hz 전원 이동 | \(50×5=250\) | **500** | **≈90** |
| 몹 3.33Hz 50기 **전부** 이동 | \(≈167\) | **≈333** | **≈30** |
| 몹 20%만 이동 | | ≈67 | ≈6 |
| PC 중 50%만 이동(`_minStep` 정지 억제 반영) | | 250 | ≈45 |

- **현재 행·5Hz·전원 이동:** **PC 부하 > 몹**.  
- **실전:** 정지는 보고 안 함(`spacetime_world_presence.dart:28-31, 128`); 어그로 밖 몹은 미이동 시 update 없음(`world.rs:1518-1520`) → 몹 부하는 사냥 밀집도에 민감.  
- **서버 총 egress(균등·구독자≈50):** 각 행 fan-out 합 ≈ 클라 수신 합  
  PC ≈ \(1000×90\) KB/s ≈ **90 MB/s** 자리 + 몹(전 이동 가정) ≈ **30 MB/s** 자리(헤더·압축 미포함).  
- **최적화 후**(Pos≈22B·2Hz, 몹 위치≈40B, 정지 미기록): PC ≈4.4 KB/s·클라; 몹 전 이동 시 더 큼 — **이후 재측정**.  
- **현행 전체 구독:** PC만 \(10N^{2}\) 행 이미지 → N=1000에서 **1e7/s·~1.8GB/s**(`GAME-SERVER.md:189-203`). AOI의 핵심은 구독자 축을 \(N\to A\)로 바꾸는 것.

### 3.6 수정·보완 포인트 (적용 형태, 읽기 전용 스케치)

**A. 서버 스키마 (`world.rs`) — 맨 끝 + default**

```rust
// WorldPlayer 말단(last_damaged_at 다음)
#[default(0u32)]
pub sub_chunk: u32, // chunk_pc(grid_x, grid_y), C_PC=75
// index: by_sub_chunk btree([sub_chunk])

// Monster: 기존 chunk(home,32) 유지 + 말단 추가
#[default(0u32)]
pub sub_chunk: u32, // chunk_mob(grid_x, grid_y), C_MOB=27, 현재 좌표
// index: by_sub_chunk

const SUB_CHUNK_PC_TILES: f32 = 75.0;
const SUB_CHUNK_MOB_TILES: f32 = 27.0;
// CHUNK_TILES=32 는 AI/home 전용으로 유지
```

**갱신:** `enter_world` / `move_to`(`world.rs:1078-1083`) / `teleport_to` / 리스폰; `monster_ai` 이동·귀환 시 **현재 좌표 `sub_chunk`**, home `chunk`는 스폰·리스폰; **좌표 불변이면 update 금지**.

**B. 클라 구독** — `kWorldSubscriptions` 고정 전체(`cyborg_connection.dart:39-44`) 제거 → 동적 9+9 OR.

```sql
SELECT * FROM world_player WHERE sub_chunk = ? OR ... -- 9
SELECT * FROM monster WHERE sub_chunk = ? OR ...     -- 9
```

**C. 재구독 + 히스테리시스 + generation**

- 상태: `center_chunk`, `query_set_id`, `generation`.  
- 청크가 바뀌어도 **중심 청크 사각형에서 margin(≈0.2\(C\)) 안이면 유지** — PC ≈15타일, 몹 ≈5타일.  
- **새 subscribe 성공 후에만 옛 unsubscribe** (역순 시 순간 소실).  
- `_generation` 패턴(`spacetime_world_presence.dart:36-80`, `spacetime_leaderboard.dart:43-66`) **재사용 가능**하나, 현재는 **입장 1회 전체 구독**뿐 — **이동 기반 청크 재구독 루프는 신규 구현**.

**D. 렌더 상한**

- `_syncRemotePlayers`(`641-663`): 거리 정렬 **max 50**.  
- `_refreshMonsterStreaming`: `_maxActiveMonsters` 140→**50**, r 60→**≈40–45**(구독 창과 정합).  
- `others`(`215-230`)는 수신 전원 — 상한은 여기 또는 렌더 직전.

**E. `monster_ai` 공간 해시** — 플레이어를 셀에 먼저 버킷(`world.rs:1479-1487`, `GAME-SERVER.md:273-281`). AOI 50과 독립이나 동접 1000 전제.

**F. 후속** — 세로 분할 `WorldPlayerPos(character_id,x,y,sub_chunk)` + 보고 2Hz(`GAME-SERVER.md:259-306`); `remote_player.dart:18-20, 83-85` 보간/외삽 조정.

### 3.7 “50+50 보장”과 안전지대

| 수단 | 보장 | 미보장 |
|---|---|---|
| \(C_{pc}=75\) / \(C_{mob}=27\) 3×3 | **분산 시 평균** 수신≈50 | 집결·링 피크 ≫50 |
| 클라 씬닝 50+50 | 화면·로컬 CPU | **이미 받은 행의 egress** |
| 서버 membership/RLS | 대역 상한 가능 | experimental·비용(`GAME-SERVER.md:364-368`) |

안전지대 50×50(`world.rs:70-73`): 입·리스폰 거점. **200~1000명 집결 시 창 크기와 무관하게 수신≈집결 인원** → ① 붕괴. 대책: 표시 50 강제, 거점 분산·입장 제한, public 전체 구독 차단은 **보안 별 결정**(`lib.rs:15-16` 불일치).

**성립 조건:** 동접 1000 **분산** + 종류별 면적 구독 + 표시 50+50 + (권장) AI 해시·정지 몹 미기록·세로 분할·2Hz. **한 점 1000 집결은 설계로 회피**(`GAME-SERVER.md:415-419`).

## 4. 리스크 · 함정

- **PC 청크(75)로 몹까지 구독** → 평균 수백 기 수신, “몬스터 50” 즉시 실패.  
- **home `chunk` 구독 재사용** → 현재 위치와 불일치.  
- **OR 49(안 B)** → 구독 관리·스냅샷 비용 급증.  
- **재구독 순서 역전 / 히스테리시스 없음** → 소실·경계 진동.  
- **무변 monster update** → AOI 안에서도 3.33Hz×2 고정 비용.  
- **마이그레이션:** 중간 삽입·default 없음 → 기존 행 실패(`world.rs:301-307`).  
- **표시 상한만 + 전체 구독** → egress는 여전히 \(N^{2}\).  
- **public 표 치트 전체 구독** — 청크 구독은 정상 클라 절약만.  
- **뷰포트 크기로 구독 축소** → 가장자리 팝인.  
- **“50”을 평균으로만 설계** → 링·안전지대에서 제품 약속 붕괴.

## 6. 불확실 · 미확인

- 배포 DB **실제 몹 행 수**(`rebuild`/`bootstrap` `placed` 로그 실측).  
- BSATN **와이어 바이트**(압축·배칭·Identity 인코딩) — 180/90·161/79 모두 추정.  
- 다중 OR 9·49의 **서버 fan-out 한도**, SDK 2.3.1 vs 서버 2.7.x.  
- 레벨 링에서의 **p95 수신 몹 수**(시드 시뮬레이션 없이 확정 불가).  
- “50”이 **평균 / p95 / 절대 상한** 중 무엇인지 — **제품 결정**.  
- 월드 표 **public 유지** 여부(보안).  
- 줌 극단·해상도별 뷰포트 UX.  
- 작업공간 루트 `cache`에는 게임 소스가 없고 실체는 `tmp/games/actionrpg` — 본 분석은 그 트리 기준.

결정적 좁히기: 동일 시드에서 (a) \(C=75\) 단일 구독 시 수신 몹 히스토그램, (b) 75/27 이중 구독, (c) 안전지대 200·1000 집결 수신 수를 봇으로 측정.

## 7. 자기 비판으로 바로잡은 것

- ❌ 철회: “**반드시** 종류별 청크 **한 변**을 나눠야만 한다”는 유일한 구현 서술 — 동일 \(C=32\)에 PC **7×7**·몹 3×3로도 평균 면적 목표는 성립(`9` 대신 \(K^{2}\) 조절). 다만 OR 49개 비용으로 A안이 우세.  
- 🔁 수정: 행 크기 **161/79 단독 단정** → 필드 합 고정 ≈133B+문자열 및 문서 **≈180/90**(`GAME-SERVER.md:187`) 범위; 50+50 결론(PC>몹, 최적화 후 역전 가능)은 자릿수 동일.  
- 🔁 수정: generation이 “이미 청크 재구독에 쓰인다”는 인상 → **입장/퇴장 레이스 방지용**이며 청크 이동 루프는 **신규**(`spacetime_world_presence.dart:36-80, 68-112`).  
- 🔁 수정: 트래픽 “5Hz 전원”을 일상 값처럼 쓴 부분 → **`_minStep`·정지 미보고·어그로 밖 몹 미기록**으로 실효는 더 낮음; 최악 상한으로 명시.  
- 🔁 수정: 뷰포트 “11~45” 단정 → AABB 근사식 \(W/128+H/64\)와 줌 설계로 **대략 12~22(기본)·줌아웃 시 ~2배**; 코드 실측 권고.  
- ➕ 추가: **안 B 수치**(7×7×32²×0.001≈50.2)와 OR 비용 비교.  
- ➕ 추가: 레벨 링·band≈2.3로 **균등 역산 대비 피크 몹 과다** 가능성 강화(`world.rs:872-880`).  
- ➕ 추가: `lib.rs:15-16` vs 월드 `public` 불일치 — 치트 전체 구독·보안 경계.  
- ➕ 추가: 구독 창 한 변 81에서 r=60 스트림은 **가장자리 무데이터 필터** 가능 → r을 AOI에 맞출 것.  
- 살아남은 핵심: 구독 LIMIT 불가, 전체 구독 현행, WP chunk 없음, Monster home chunk, AI O(근처×N), 이중 겹 AOI, \(C\approx75/27\), 표시 상한 필수, 집결 설계 회피 — 모두 재확인 자료와 일치.
