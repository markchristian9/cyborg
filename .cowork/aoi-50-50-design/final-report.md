# 종합 검토 — aoi-50-50-design

> 요청: AOI 영역을 어떻게 설정하는지 설명하고, AOI 에 몬스터 50, PC 50 을 동시에 보여주는 경우, 어떻게 현재 프로젝트를 업데이트하면 좋을지 설명하고 수정/보완할 내용을 알려주세요.
> 분석: claude · codex · grok (**kimi 는 분석 도중 제한 시간에 잘려 제외**)
> 종합: 2026-08-05 · 읽기 전용 검증 — 작업공간 미수정

## 1. 결론

**몬스터 50 과 PC 50 은 하나의 청크 크기로 만들 수 없다. 청크를 종류별로 나누고, 인원 상한은 렌더링에서 강제해야 한다.**

1. **밀도가 8 배 다르다.** 플레이어는 월드 전역에 0.001 명/타일², 몬스터는 배치 링 안에 0.00822 기/타일². 같은 목표 50 을 면적으로 역산하면 청크가 **PC 74 타일 / 몬스터 26 타일**로 갈린다.
2. **몬스터는 면적으로 50 을 자를 수 없다.** 레벨이 반지름에 선형 매핑되어 밀도가 `2.12/r` 로 변한다 — 레벨 1 구역이 레벨 200 구역의 **13 배** 조밀하다. 평균 50 으로 맞춰도 실측은 27~335 사이를 오간다. **몬스터의 "50" 은 청크가 아니라 클라이언트 표시 상한으로만 만들어진다.**
3. **그래서 몬스터 구독 청크는 26 이 아니라 기존 `CHUNK_TILES = 32` 를 재사용하는 것이 맞다.** 어차피 인원을 못 자르므로 남는 기준은 **화면 보장 반경**이고, 32 는 최대 축소 시 화면 반폭 22.4 타일을 덮는다. 새 상수를 만들 이유가 없고 이미 `Loot` 이 같은 격자를 쓴다.
4. **9 청크는 화면 대비 196 배 과잉이지만 줄이면 안 된다.** 화면에 실제로 보이는 그리드 면적은 **약 251 타일²**뿐이다. 그러나 청크를 화면 크기로 줄이면 최대 축소 시 화면 구석이 구독 밖으로 나가고 재구독이 진동한다. **과잉을 줄이는 레버는 청크 축소가 아니라 행 크기와 보고 주기다.**
5. **최적화하면 병목이 몬스터로 넘어간다.** 지금은 플레이어가 지배적이지만, 세로 분할 + 2Hz 로 플레이어를 4.4MB/s 로 내리면 몬스터가 11.5MB/s 로 역전한다. 몬스터는 클라이언트가 주기를 조절할 수 없는 축이라(`_inFlight` 백프레셔가 안 걸린다) 서버 쪽 처방이 필수다.
6. **세 AI 가 모두 놓친 것 하나** — `SELECT * FROM loot` 도 전체 구독이다. `Loot` 은 이미 `chunk` 컬럼과 `by_chunk` 인덱스를 가지고 있어 **가장 싸게 고칠 수 있는 대상인데 아무도 언급하지 않았다.**

## 3. 합의 — 검증 통과

- **`WorldPlayer` 에 구독용 청크 컬럼이 없다.** 확인: [world.rs:267-359](../../spacetimedb/src/world.rs#L267) 에 `chunk` 문자열 0 회. 선행 조건이다.
- **`Monster.chunk` 는 집 좌표 기준이다.** 확인: [world.rs:414-423](../../spacetimedb/src/world.rs#L414) 주석과 [world.rs:798](../../spacetimedb/src/world.rs#L798) `chunk: chunk_of(x, y)` — 배치 시점의 집 좌표다.
- **자동 마이그레이션 조건은 "맨 끝 + 기본값".** 확인: [world.rs:301-307](../../spacetimedb/src/world.rs#L301) 이 코드 주석으로 못박고 있고, `next_teleport_at`~`last_damaged_at` 일곱 컬럼이 전부 이 규칙으로 붙어 있다.
- **구독 SQL 로 인원을 자를 수 없다.** `LIMIT`·`ORDER BY`·산술식 전부 불가([GAME-SERVER.md](../../GAME-SERVER.md) §2.4). 세 AI 가 독립적으로 같은 결론.
- **원격 플레이어에 표시 상한이 없다.** 확인: [action_rpg_game.dart:665](../../lib/game/action_rpg_game.dart#L665) `_syncRemotePlayers` — `presence.others` 전부를 순회해 `world.add` 한다. 개수 상한도 거리 필터도 없다. 몬스터는 [:207](../../lib/game/action_rpg_game.dart#L207)·[:210](../../lib/game/action_rpg_game.dart#L210) 에서 60 타일·140 기로 자르는데 사람은 안 자른다.

## 4. 이견 — 자료로 판정

### 쟁점 A: 몬스터 밀도의 분모는 무엇인가

- claude: 몬스터가 실제로 놓이는 **사각 링 면적 912,288 타일²** → ρ = 0.00822
- codex·grok: **월드 전체 1,000,000 타일²** → ρ = 0.0075

**판정: claude 가 맞다.**

**근거**: [world.rs:930-960](../../spacetimedb/src/world.rs#L930) `cluster_center` 를 직접 열어 확인.

```rust
let inner = SAFE_ZONE_TILES / 2.0 + 12.0;      // 50/2 + 12 = 37
let outer = WORLD_TILES / 2.0 - 24.0;          // 1006/2 - 24 = 479
let band = (outer - inner) / MONSTER_MAX_LEVEL as f32;   // 442/200 = 2.21
let wobble = (... - 0.5) * band * 6.0;                   // ±6.63
```

`ring_direction` 이 정사각 둘레이므로 군집 중심은 **반경 37~479 의 사각 링 위에만** 놓인다. 안전지대와 월드 가장자리에는 몹이 없다. 그리고 **플레이어는 그 링 안에서 사냥한다** — 사람이 실제로 겪는 밀도는 링 밀도다.

```text
링 면적 = (2×479)² − (2×37)² = 917,764 − 5,476 = 912,288 타일²
ρ_monster = 7,500 / 912,288 = 0.00822 기/타일²
```

차이는 10% 로 자릿수를 바꾸지 않지만, **분모를 어디로 잡느냐가 "몬스터는 균등 분포가 아니다" 라는 다음 결론으로 이어진다는 점이 중요하다.**

### 쟁점 B: 몬스터 구독 청크를 얼마로 할 것인가

- claude: **32** (기존 `CHUNK_TILES` 재사용, 화면 보장 반경 기준)
- codex·grok: **27** (평균 인원 50 역산)

**판정: claude 가 맞다.** 이유는 claude 가 든 것보다 하나 더 있다.

**근거 1 — 면적으로 인원을 자를 수 없다.** [world.rs:930](../../spacetimedb/src/world.rs#L930) 에서 레벨→반지름이 선형(`t = (level-1)/199`)이고 레벨마다 3 군집이다. 반경 r 의 얇은 링에 들어가는 군집 수는 `3·dr/2.21`, 그 링의 면적은 `8r·dr`(사각 링) 이므로:

```text
몬스터 밀도(r) = 12.5 × (3/2.21) / (8r) = 2.12 / r

r=37  (레벨 1)   → 0.0573 기/타일²   ← 50 기를 담는 청크 9.9 타일
r=250 (레벨 97)  → 0.00848            ← 25.6 타일
r=479 (레벨 200) → 0.00443            ← 35.5 타일
```

**중심부가 외곽의 13 배 조밀하다.** 전역 평균으로 역산한 26~27 은 중간 지대에서만 맞고, 저레벨 구역에서는 약 335 기, 최외곽에서는 약 27 기가 된다. 어느 값을 골라도 인원은 보장되지 않는다.

**근거 2 — 그러면 남는 기준은 화면 보장 반경이다.** 3×3 구독의 보장 반경(플레이어가 자기 청크 모서리에 섰을 때 구독 경계까지의 최소 거리)은 **C 타일**이다. 최대 축소 시 화면 AABB 반폭이 약 22.4 타일이므로 `C ≥ 23` 이어야 한다. 26 도 27 도 32 도 모두 충족하지만 **32 가 여유가 가장 크다.**

**근거 3 (내가 추가) — 프로젝트에 이미 32 격자 선례가 있다.** [world.rs:431-435](../../spacetimedb/src/world.rs#L431) 의 `Loot` 테이블이 `chunk` 컬럼과 `by_chunk` 인덱스를 이미 가지고 있고, [world.rs:1716](../../spacetimedb/src/world.rs#L1716) 에서 `chunk: chunk_of(lx, ly)` 로 채운다. 몬스터·드롭이 같은 격자를 쓰면 **클라이언트가 청크 번호 집합을 한 번만 계산해 두 구독에 재사용**할 수 있다. 새 상수(26/27)를 만들면 격자가 셋으로 늘어난다.

→ **몬스터·드롭 구독 청크 = 32(기존 `chunk_of` 재사용), PC 구독 청크 = 74(신규).**

### 쟁점 C: 집 좌표 청크의 보장 반경

- claude: **6 타일** — 직전 분석(`.cowork/scale-1000-aoi-100/final-report.md` §6)의 "AI 용도로는 안전하다" 를 정정
- codex·grok: 언급 없음 / "home 기준" 사실만 지적

**판정: claude 가 맞다. 내 직전 보고서의 판정이 부정확했다.**

**근거**: 논리를 다시 세워 확인했다.

```text
플레이어에서 거리 d 에 있는 몹이 3×3 조회에 잡히려면 그 몹의 '집' 이 3×3 안에 있어야 한다.
몹은 집에서 최대 MONSTER_MAX_ROAM_TILES(26) 만큼 벗어날 수 있다 (world.rs:152)
플레이어가 자기 청크 모서리에 섰을 때 3×3 경계까지의 최소 거리 = 32
→ d + 26 ≤ 32  →  d ≤ 6
```

직전 보고서는 "roam 26 < 청크 32 이므로 안전" 이라고 썼는데, **비교해야 할 것은 roam 과 청크 변이 아니라 roam 과 보장 반경이었다.** 실제 영향은 제한적이다 — 몹이 집에서 26 타일까지 벗어나려면 추격 중이어야 하고 리쉬 16 타일([world.rs:148](../../spacetimedb/src/world.rs#L148))이 먼저 걸린다. 그러나 **구독용으로 이 컬럼을 재사용하면 화면 반폭 11~22 타일보다 작아 화면 구석의 몹이 그냥 안 온다.** 현재 좌표 기준 새 컬럼이 반드시 필요하다.

### 쟁점 D: `_generation` 패턴을 재구독에 재사용할 수 있는가

- claude: "그대로 재사용할 수 있다"
- grok: "입장/퇴장 레이스 방지용이며 청크 이동 루프는 신규다"

**판정: grok 이 맞다.**

**근거**: [spacetime_world_presence.dart](../../lib/spacetime/spacetime_world_presence.dart) 의 `_generation` 사용처 전부를 확인했다 — `:72` 입장 시 `++_generation`, `:80`·`:92` 레이스 체크, `:108` 퇴장 시 `_generation++`. **입장·퇴장 경계에서만 쓴다.** 그리고 `_querySetId` 는 `:33` 에 **단일 슬롯**이라 겹침 전환("새 것 먼저 걸고 옛 것 나중에 해제")을 표현할 수 없다.

→ 패턴의 *아이디어*(세대 번호로 늦게 도착한 응답을 버린다)는 재사용하되, **재구독 루프와 2 슬롯 구조는 새로 만들어야 한다.**

## 5. 고유 통찰 — 하나만 발견했으나 검증됨

- **claude: 화면에 실제로 보이는 그리드 면적은 251 타일²다.** 확인: [iso.dart:5-9](../../lib/game/iso.dart#L5)·[:62-67](../../lib/game/iso.dart#L62) 에서 `gridToScreen = ((gx−gy)·64, (gx+gy)·32)`. 야코비안 행렬식 `|64·32 − (−64)·32| = 4,096 px²/타일²`. 1280×720 화면·zoom 0.947 이면 `1352×760/4096 ≈ 251 타일²`. **PC 청크 74 의 3×3(49,284)은 화면의 196 배**이고, 균등 분포에서 AOI 안 50 명 중 화면에 들어오는 것은 0.25 명이다. 대역폭의 99.5% 가 화면 밖 좌표다.

- **claude: 사망 리스폰이 좌표를 바꾸는 네 번째 지점이다.** 확인: [world.rs:1952-1957](../../spacetimedb/src/world.rs#L1952) `let (cx, cy) = world_center(); ... grid_x: cx`. `move_to`·`teleport_to`·`enter_world` 는 눈에 띄지만 이건 `apply_damage_to_player` 안에 있어 놓치기 쉽다. **여기서 청크를 갱신하지 않으면 죽은 사람이 안전지대에 서 있는데 구독상으로는 사냥터 청크에 남아, 본인 화면은 텅 비고 남들 화면에는 유령이 남는다.**

- **claude: `_maxActiveMonsters` 는 거리순이 아니라 선착순이다.** 확인: [action_rpg_game.dart:1201](../../lib/game/action_rpg_game.dart#L1201) `if (_activeMonsters.length >= _maxActiveMonsters) continue;`. 140 일 때는 잘 안 드러나지만 **50 으로 조이면 "가까운 50 기" 가 아니라 "먼저 순회된 50 기" 가 되어 눈앞의 몹이 안 그려진다.** 상한을 내리는 것과 거리순 정렬을 넣는 것은 한 묶음이다.

- **(내 발견) `SELECT * FROM loot` 도 전체 구독이며, `Loot` 은 이미 청크를 갖고 있다.** 확인: [cyborg_connection.dart:46](../../lib/spacetime/cyborg_connection.dart#L46) 이 전체 구독이고, [world.rs:431-435](../../spacetimedb/src/world.rs#L431) 는 이미 `index(accessor = by_chunk, btree(columns = [chunk]))` 를 갖고 있으며 [world.rs:1716](../../spacetimedb/src/world.rs#L1716) 이 `chunk_of(lx, ly)` 로 채운다. **서버 변경이 전혀 필요 없고 구독 문자열만 바꾸면 되는, 가장 싼 개선인데 세 AI 가 모두 놓쳤다.**

## 6. 반증 — 근거가 틀린 주장

- **codex: "Dart SDK 2.4.0"** — ❌ 실제 설치본은 **2.3.1** 이다(`~/.pub-cache/hosted/pub.dev/spacetimedb_sdk-2.3.1/`). 직전 보고서에서 이미 같은 오류를 지적했는데 반복됐다. 인용한 `subscription_manager.dart`·`table_cache.dart` 의 **동작 서술 자체는 2.3.1 에서도 유효**하나, 라인 번호는 신뢰할 수 없다.

- **claude: `_monsterReleaseRadius` 는 `:198`, `_maxActiveMonsters` 는 `:201`** — ❌ 실제로는 **`:207`, `:210`** 이다. 값(60, 140)은 맞다. 인용 라인만 어긋났다.

- **claude: 사망 리스폰이 `world.rs:1762-1777`** — ❌ 실제로는 **`:1952-1957`** 이다. 지적 자체는 유효하다.

- **claude: "`_generation` 패턴을 그대로 재사용할 수 있다"** — ⚠️ §4 D 에서 판정한 대로 부정확하다. grok 의 서술을 채택한다.

## 8. 미해결 · 사람 판단 필요

- **"AOI 에 50+50" 의 해석.** ⓐ *구독 범위 안에 50+50* 이면 본 보고서 그대로다. ⓑ *한 화면에 50+50* 이면 화면 251 타일²에 밀도 0.199/타일² 가 필요하고, 이는 플레이어 균등 밀도의 199 배·몬스터 군집 내부 밀도(0.0346)의 5.8 배다 — **청크 설계가 아니라 월드 배치 밀도(`CLUSTER_MIN/MAX`, `CLUSTERS_PER_LEVEL`)나 동접 목표를 바꿔야 하는 문제**다. 본 보고서는 ⓐ로 진행했다.
- **동접 1,000 이 여전히 전제인가.** PC 청크 74 는 `1,000/1,000,000` 에서 나왔다. 동접 500 이면 105 타일, 2,000 이면 52 타일이다.
- **저레벨 구역에서 `_maxActiveMonsters = 50` 의 체감.** 그 구역은 청크 32 의 3×3 에 평균 300 기 이상이 있어 대부분이 안 그려진다. "사냥터가 텅 비어 보인다" 로 나타날 수 있다.
- **`_monsterReleaseRadius` 를 줄이면 자동 사냥·파티 추종과 충돌하는지.** [auto_hunt.dart](../../lib/game/systems/auto_hunt.dart) 가 60 타일 안의 몹 존재를 전제하고 있다면 회귀가 난다. 이번 구현에서는 **이 값을 건드리지 않는다.**
- **배포된 테이블에 btree 인덱스 추가가 자동 마이그레이션으로 처리되는지 미확인.** [world.rs:301-307](../../spacetimedb/src/world.rs#L301) 이 명시하는 것은 *컬럼* 조건뿐이다. 배포 전 로컬 인스턴스에서 확인해야 한다.
- **모든 수치가 계산이며 측정이 아니다.** 부하 시험이 실행된 기록이 없다.

**적용 중 발견해 바로잡은 것** (권고에 없었음):

- **`sub_chunk` 를 처음에 구조체 중간에 넣었다.** 편집 시점에 `last_damaged_at` 이 마지막인 줄 알았으나, 실제로는 뒤에 `last_attack_at`·`attack_dir_x`·`attack_dir_y`·`attack_skill` 이 있었다(다른 세션이 같은 파일을 동시에 편집 중이었고, 도구가 "파일이 디스크에서 바뀌었다" 고 알렸다). **자동 마이그레이션 조건(맨 끝) 위반**이라 맨 끝으로 옮기고 바인딩을 다시 생성해 `subChunk` 가 마지막인 것을 확인했다.
- **Dart 바인딩은 `spacetime generate` 로 못 만든다** — CLI 가 dart 를 지원하지 않는다. `dart run spacetimedb_sdk:generate --project-path ./spacetimedb` 를 쓴다. 배포 없이 로컬 모듈에서 생성된다.
- 내 변경으로 깨진 테스트 2 개(`kWorldSubscriptions` 참조)를 새 함수로 고쳤다.
