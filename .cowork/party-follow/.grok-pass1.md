## 0. 탐색 로그 (ToT)

- **세운 가설**
  - (1) **해피패스 성립설** — 초대·수락·파티장 추종·자동 사냥 배선이 코드상 이어져 있어, AOI 안·정상 접속 중에는 동작한다.
  - (2) **추종 경로 단절설** — `_followTarget`이 `presence.others`(AOI 청크 구독)에만 의존해, 리더가 이웃 청크 밖으로 나가면 추종이 구조적으로 끊긴다.
  - (3) **서버 좀비 상태설** — `on_disconnect`/`leave_world`가 파티·`following`을 안 지워, 끊김·이탈 후 멤버십·추종 의사가 서버에 남아 증상이 누적된다.
  - (4) **hunt lead 미구현이 요구와 정면 충돌** — 사용자는 “이끌기”를 요구하는데 코드에는 파티장 고정 추종만 있다.

- **검증**
  - 가설 1 → `party.rs` 초대·view, `PartyInviteCard`, `_updatePartyFollow`→`autoHunt`→`tryMelee`→`Enemy.applyDamage`→`presence.attack` 경로 확인 → **지지(해피패스)**.
  - 가설 2 → `worldSubscriptionsFor` 3×3 청크 + `_followTarget` null→`lost` → **지지(치명)**.
  - 가설 3 → `lib.rs:on_disconnect`, `leave_world`가 `world_player`만 삭제 → **지지**.
  - 가설 4 → `hunt_lead` 0건, `set_following`이 `leader_character_id` 고정 → **지지**.

- **가지치기**
  - “`changes`가 `my_party`를 안 들어 UI가 전혀 안 갱신된다”는 **현재 UI가 매 프레임 poll**(`PartyPanel.render`/`PartyInviteCard.render`)이라 **당장의 치명도는 낮음**. 다만 hunt lead를 `Party` 행에 두면 Listenable 기반·상태 전이 배너에 필요 → **보류·권고 유지**, “지금 화면이 안 돌아간다” 수준으로는 과장하지 않음.
  - “추종 중 자동 공격이 로컬 전용 몹만 친다” → 서버 동기 `Enemy.serverId` + `presence.attack` → **반증**.

## 1. 결론 요약

**현재 파티는 “멤버십·초대·파티장 고정 추종·추종 시 자동 사냥” 해피패스는 코드 경로상 이어져 있으나, MMORPG 단일 월드 기준으로는 ‘올바로 동작’이라고 말할 수 없다.**  
치명 결함은 (1) **AOI 경계에서 리더를 못 보면 추종을 끊는 구조**, (2) **접속 종료 시 파티/`following` 미정리**, (3) **요청된 ‘파티 이끌기’ 전무**, (4) **kick UI·추방 알림 부재**다.  
시나리오 (가)(다)(사)는 대체로 성립하고, (나)는 AOI 안에서만, (라)(마)(바)는 부분 성립·경계에서 끊기며, hunt lead는 설계안 재검증 결과 **직전 종합(Party 열 3개 + lead_seq + AOI 우회)이 여전히 타당**하다.

## 3. 상세 분석

### 3.1 시나리오 코드 경로 판정

#### (가) A 초대 → B 초대 카드

| 단계 | 경로 | 판정 |
|---|---|---|
| A 초대 | `PartyPanel` 근처 요원 → `invitePlayerToParty` → `invite_to_party` | **성립**. 파티 없으면 서버가 생성(`party.rs:287-299`). |
| B 수신 | B가 `kPartySubscriptions`의 `my_party_invites` 구독 → `PartyInviteCard._invite` | **성립**. 패널을 안 열어도 카드 표시(`party_panel.dart:449-452`). |
| 20초 만료 | 클라 `isExpiredAt`로 카드 숨김; 수락 시 서버 `expires_at` 재판정 | **표시 성립, 카운트다운 UI 없음**. 시계 오차는 표시만 틀림(서버가 최종 거절). |
| 수락 후 목록 | 멤버 insert → 양쪽 `my_party_members` 갱신 | **성립**. |
| 거절 사유 화면 | `_runPartyAction` + `SpacetimeDbReducerException` | **성립** — “이미 다른 파티”, “가득 찼다” 등. |
| 함정 | `invitePlayerToParty`가 **호출 직후** “초대했다” 배너(`:939`) | 실패해도 성공 배너가 먼저 뜸 → 이어서 거절 배너. |

다중 초대 시 카드는 **목록 첫 미만료 1건만** 표시(`party_panel.dart:490-495`).

#### (나) B가 파티장 추종 → A 추적

```
togglePartyFollow
  → party.setFollowing(true)          // 서버: following = leader_character_id
  → 매 프레임 _updatePartyFollow
      → party.isFollowing (멤버 행)
      → _followTarget() = presence.others ∩ leaderCharacterId
      → PartyFollowController: rejoin / anchor
      → autoHunt.moveAnchor | enable
```

- **AOI 안·리더 생존**: 끊김 없이 성립.
- **리더가 청크 3×3 밖**: `_followTarget()==null` → `lost` → `_stopFollowing` → 서버 `set_following(false)`.  
  재합류 거리(25타일)보다 **구독 반경 문제**가 먼저 터질 수 있음(청크 경계·히스테리시스 1.5s).
- **설계 어긋남**: 서버는 `following_character_id`에 “누구”를 담지만, 클라는 **`leaderCharacterId`만** 본다(`action_rpg_game.dart:889-901`). 지금은 set_following이 리더만 넣어서 우연히 동치. hunt lead 시 즉시 깨짐.

#### (다) 추종 중 자동 공격

- 후보: 로컬 `enemies` 리스트 = 서버 `monster` 스냅샷 스트리밍(`_refreshMonsterStreaming`).
- 공격: `AutoHuntAction.attack` → `player.tryMelee(target:)` → 스윙 중반 `_resolveMeleeHit` → `Enemy.applyDamage` → **서버 몹이면** `presence.attack(serverId)` → `attack_monster`.
- 앵커: 추종 `anchor`가 매 프레임 리더 그리드로 이동 → 리더 주변 사냥 이어짐.
- **성립.** “순수 로컬 웨이브 몹만”이 아님. 경험치는 서버 몹은 서버 지급(`onEnemyKilled`).

주의: 추종 중 자동사냥이 꺼져 있으면 `anchor` 분기에서 **강제 enable**(`:880-883`) — “추종=자동사냥 한 몸” 정책.

#### (라) disband / leave / kick

| 행위 | 서버 | 클라 | 판정 |
|---|---|---|---|
| leave | `remove_member` — following 정리, 리더 승계 또는 해산 | 추종 중이면 `_stopFollowing` 후 leave | **정리 성립**. 낙관 배너 “나왔다” 후 실패 가능. |
| disband | 멤버·초대·파티 삭제 | 배너 + disband; 멤버 행 삭제로 `isFollowing` false | **서버·클라 성립**. 자동사냥은 남을 수 있음. |
| kick | `remove_member` 동일 | **UI 없음** (`kick` 호출 경로 0) | **기능 미노출**. 추방당한 쪽 전용 배너도 없음(목록만 사라짐). |

#### (마) 파티장 접속 끊김

- 서버: `world_player`만 삭제. **Party / PartyMember / following 유지**.
- 추종자 클라: presence에서 리더 실종 → `lost` → 로컬 추종 해제 + (가능하면) `set_following(false)`.
- **증상**: 파티 패널에 리더 “접속 중이 아님”, 멤버십 잔존, 재초대 불가(“이미 파티”), 리더 재접속 시 파티 그대로·추종은 이미 끊긴 상태.  
- 다른 멤버가 리더를 따르던 `following`은 클라가 각자 풀지 못하면 서버에 남을 수 있음(네트워크 실패 시).

`leave_world`/로그아웃도 `party.detach()`만 하고 `leave_party` 없음 — 설계 의도(월드 밖 파티 유지, `party.rs:619-622`)이나 **강제 종료와 구분 없이 좀비 가능**.

#### (바) 파티원 사망 → 부활 후 추종

- `onPlayerDied`: 자동사냥만 끔, 추종 서버 상태 유지.
- 죽은 동안 `_updatePartyFollow` early return.
- 부활 후 살아 있으면 다시 판단; 리더가 멀면 `giveUpDistanceTiles(120)` 또는 rejoin timeout(8s)로 lost.
- **의도적 재개**. 안전지대 반대편이면 끊김 — 경로 탐색 없음 전제상 타당.

리더 사망: `hold`로 앵커 유지, 추종 끊지 않음 → 부활 후 안전지대 재집결(라리엔 §10.5.5와 정렬).

#### (사) 12명 만석 · 이미 파티인 대상

- 서버: `파티가 가득 찼다(최대 12명).` / `상대가 이미 다른 파티에 있다.`
- 클라: `_runPartyAction` 배너.
- **성립**. 단 초대 버튼은 클라에서 만석을 막지 않음(멤버 목록 길이로 `isFull`은 있으나 근처 요원 초대 경로에서 미사용) → 왕복 후 거절.

### 3.2 알려진 결함 2개 재확인

1. **AOI 추종 끊김** — **여전히 실재.** `giveUpDistance=120`보다 먼저, **구독 밖 = 실종**으로 처리.
2. **`changes`에 `my_party` 없음** — 코드 사실. 현재 Flame UI는 poll이라 초대/멤버 위주 갱신은 동작. **`promote`만 하고 following 변경이 0건이면** 리더 표식은 다음 render의 `_party` 조회로는 갱신됨(매 프레임 `myParty` 캐시 읽기). Listenable 의존 UI·hunt lead 필드 전이 배너에는 여전히 구멍.

### 3.4 파티 이끌기 설계 재검증

직전 종합안:

- `Party` 맨 끝 `hunt_lead_character_id` / `hunt_lead_seq` / `hunt_lead_name` + `#[default]`
- `start_hunt_lead` / `stop_hunt_lead` / `accept_hunt_lead(lead_seq)`
- `set_following(true)` 파티장 고정 **폐기**, accept가 대체
- `my_hunt_lead_target` (좌표·생사)

**여전히 타당.** 지지 이유:

1. `following_character_id` 주석이 이미 hunt lead 확장 전제(`party.rs:114-116`).
2. 파티당 1세션을 스키마로 강제 — 별도 UNIQUE 표 불필요.
3. 전원 `my_party` 구독 → 별도 초대 표 없이도 “이끌기 시작” 방송 가능(라리엔 UDP 초대 표와 전송 모델 다름).
4. `lead_seq`는 stale 수락 차단(초대 id와 동급, `accept_invite` 주석이 라리엔 leadSeq를 인용).

**보완·반증 포인트 (더 나은 대안 후보):**

| 항목 | 직전안 | 재검증 의견 |
|---|---|---|
| AOI 우회 | `my_hunt_lead_target` view | **필수 문제.** 대안: `world_player` public + `character_id` unique 로 `WHERE character_id = N` 추가 구독. view는 리더 `move_to`마다 파티 전원 recompute(`party.rs:39-45` 경고). 1명 한정이라 수용 가능하나, **직접 구독이 재계산 비용·Type2 함정을 피함**. 멤버 변경 시 구독 쿼리 갱신 필요. |
| disconnect | 언급만 | **구현 필수.** lead 캐릭터 disconnect 시 hunt 세션 종료 + 그 id following clear. 멤버십 유지 vs leave는 제품 선택; 라리엔은 이탈 시 leave. |
| `set_following(true)` | 폐기 | **동의.** false만 유지(개별 추종 해제). |
| promote 일괄 following 이전 | 조건부 | **동의.** hunt 활성 중 이전 금지. |
| 누구나 이끌기 | 채택 | 라리엔·주석과 일치; 제품 확인만 남음. |

**기각할 대안:** “파티장 추종 UI 이름만 ‘이끌기’로 바꾸기” — 요청의 “다른 팀원에게 follow 버튼”·비파티장 지휘와 불일치.

### 3.5 범위 경계

| 영역 | 권위 | 비고 |
|---|---|---|
| 멤버십·초대·following 의사 | 서버 reducer | 클라이언트를 신뢰하지 않음 — 올바름 |
| 실제 이동·사냥 | 클라 `PartyFollow`+`AutoHunt` | 서버 시뮬 없음 — 전제 수용 |
| 몹 피해·킬 | 서버 `attack_monster` | 추종 사냥도 동일 경로 |
| 리더 좌표 | 현재 AOI `world_player` | 추종 SSOT 아님 → 결함 |

## 4. 리스크 · 함정

- **AOI×추종**: 수정 없이 파티 사냥은 청크 경계에서 반복 끊김 → MMORPG에서 “추종이 고장”으로 인식.
- **disconnect 좀비 파티**: 정원 슬롯 점유, 재초대 불가, following 잔존.
- **배포 스키마**: `Party` 열 추가 = maincloud publish + 바인딩 재생성; 세션 간 `generated/` 충돌.
- **view+좌표**: Type2 함정(테이블 아닌 반환 타입), 좌표 view 재전송 비용.
- **낙관 배너·setFollowing 예외**: “안 눌린 것 같음” / 상태 어긋남.
- **kick 부재**: 적대적 파티원·실수 초대 대응 불가 → 해산만이 답.
- **기존 `party_follow_test`**: 컨트롤러 순수 로직은 유지 가능; 배선·AOI·hunt는 통합/실서버 검증 필요.
- **문서 불일치**: cowork-prompt Overview의 “실시간 멀티 없음” 등과 달리 파티·월드 presence·서버 몹은 이미 존재 — 분석은 **코드 기준**.

## 6. 불확실 · 미확인

- **실서버·DTD 런타임 미실행**(읽기 전용) — 초대 카드·추종·attack_monster는 경로 추론이며 실측 로그 없음.
- **disconnect 시 멤버십 유지 vs 자동 leave** — 코드 주석은 유지 쪽, 라리엔·좀비 방지 관점은 leave 쪽. **사람 결정**.
- **`WHERE character_id = N` 구독 실측 성능·제약** — unique 필드 등식은 이론상 가능, 배포 환경 미검증 `[추측]`.
- **view가 `world_player`를 읽을 때 SpacetimeDB 2.7 재계산 빈도** — 모듈 주석 수준의 경고만 확인.
- **‘누구나 이끌기’ vs 파티장만** — 설계 권고는 누구나, 제품 확인 필요.
- **클라 시계 오차**로 초대 카드가 일찍/늦게 사라지는 실측 범위.
- **파티 12명 전원 following 시** 전송·자동사냥 부하 — 설계 상수 근거만 있고 부하 실측 없음.

---

**한 줄 판정:** 파티 1차는 “근처 초대 + 파티장 추종 + 자동사냥 연동”까지 구현됐으나, **AOI·disconnect·kick·이끌기**가 비어 있어 요청 기능 세트는 아직 올바르지 않다. 수정 우선순위는 **추종 좌표 경로 고정 → disconnect 정리 → hunt lead** 이다.
