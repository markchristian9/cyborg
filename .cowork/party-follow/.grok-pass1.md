## 3. 상세 분석

### 3.1 범위·경계

| 영역 | 권위 | 담당 팀 |
|---|---|---|
| 월드 입장·좌표·원격 PC 렌더 | 서버 `world_player` + 클라 `WorldPresence` | **다른 팀** (이미 `SpacetimeWorldPresence`·`RemotePlayerEntity` 존재) |
| 파티 멤버십·초대 | SpacetimeDB 표/reducer | **우리 팀 (신규)** |
| 추종 시 이동·사냥 실행 | 클라 `AutoHuntController` + 로컬/서버 전투 경로 | **우리 팀** (presence는 읽기만) |
| 킬/EXP/loot | 기존 `tagged_by` + `award_kill` | **변경하지 않음** (의도적) |

“먼저 월드 연결부터”는 **이미 진행·부분 완료**이므로 반복 권고하지 않는다. 단 cowork-prompt/GAME-DESIGN의 “클라가 월드 미사용” 서술은 **코드와 어긋난다**(`spacetime_world_presence.dart`, `action_rpg_game.dart:533-536`).

### 3.2 SpacetimeDB 파티 스키마 (권고 설계)

기존 원칙: 계정 계층 비공개, 월드 공개 예외는 “서로 봐야 하는 사실”만(`world.rs:33-39`). 파티 멤버십은 **소셜 상태**이므로 기본은 **비공개 표 + view**. 다만 같은 파티원이 서로를 식별하려면 view가 멤버 행을 돌려줘야 한다. Dart 생성기는 view 반환 타입을 **테이블 이름에서만** 찾는다(`GAME-DESIGN.md:680-683` 리더보드 패턴) → view 전용 “가짜 표” 또는 **기존 테이블 타입을 그대로 반환**.

**표 (모두 private, `public` 없음)**

1. `party`
   - `id: u64` PK auto_inc  
   - `leader_character_id: u64` (btree)  
   - `created_at: Timestamp`  
   - (선택) `member_count: u32` — view/iter 제약 완화용 캐시  
   - **account_id 열 금지** (공개 경로 유출 방지 철학과 동일)

2. `party_member`
   - `character_id: u64` PK (**한 캐릭터 = 최대 1 파티**)  
   - `party_id: u64` btree  
   - `joined_at: Timestamp`  
   - (선택) `is_leader: bool` — `party.leader`와 이중이 되면 promote 시 둘 다 갱신; 단일 SSOT는 `party.leader_character_id` 권장

3. `party_invite` (만료·stale 차단 = 라리엔 `leadSeq` 역할)
   - `id: u64` PK auto_inc (**invite_seq**)  
   - `party_id`, `from_character_id`, `to_character_id` (to에 btree)  
   - `created_at`  
   - 수락 시 `id` 대조 → stale/다른 파티 초대 차단

4. (2단계) `hunt_lead_session` — party leader와 **분리**
   - `party_id` unique (파티당 1 세션)  
   - `leader_character_id`, `seq: u64`, `leash_meters` 또는 tiles, `started_at`  
   - follower 목록은 `hunt_follow` 표(`character_id` PK, `session_seq`, `party_id`) 또는 member 행 플래그

**Reducer (인자로 account_id/남의 identity 금지; 전부 `require_session` + selected character + 가능하면 `require_world_player`)**

| reducer | 검증 요약 |
|---|---|
| `create_party` | 월드 입장·무소속 → party 생성, 자신을 leader member로 insert |
| `invite_to_party(target_character_id)` | 호출자가 멤버(또는 leader-only 정책), 대상이 월드에 있고 무소속, 인원 상한, invite 행 생성 |
| `accept_invite(invite_id)` | `to` = 내 캐릭터, invite 유효·미만료, 아직 무소속 → member insert, invite 삭제 |
| `decline_invite(invite_id)` | 동일 소유 검증 후 삭제 |
| `leave_party` | 멤버 삭제; leader면 promote 자동 또는 disband 정책 명시 |
| `disband_party` | leader only, 멤버·초대·hunt session 일괄 삭제 |
| `promote(target_character_id)` | leader only, 대상 같은 파티 |
| `kick(target_character_id)` | leader only, 자신 제외 |
| `start_hunt_lead` / `accept_hunt_lead(seq)` / `stop_hunt_lead` / `set_hunt_leash` | 라리엔 §10.5 동등; **이동 시뮬레이션 없음**, 상태 플래그만 |

**구독**

```text
-- 월드 입장 후 (다른 팀 kWorldSubscriptions와 병합 시 충돌 주의 → 별도 query set 권장)
SELECT * FROM my_party
SELECT * FROM my_party_members
SELECT * FROM my_party_invites   -- to = me
SELECT * FROM my_hunt_lead       -- 본인 관점 leading|following|idle
```

view는 `ctx.sender()` → session → character_id → party_member 조인. **iter 없는 view**이므로 party_id btree 인덱스 필수.

**disconnect** (`lib.rs:208-213`): `world_player` 삭제만 함. 파티 멤버 행은 남을 수 있음 →  
- 최소: 멤버 유지(재접속 후 파티 유지)  
- 추종: 리더가 `world_player`에 없으면 클라가 follow 중단 + (선택) `stop_hunt_lead`를 리더 측 on_disconnect 훅에서 서버가 종료  

권고: **`on_disconnect`에 hunt_lead 세션 종료 + (선택) 초대 만료 청소**를 명시적으로 추가. 파티 멤버십은 로그아웃/`leave_party`까지 유지할지 제품 결정.

### 3.4 추종 & 자동 사냥 (클라)

**실행 위치: 클라이언트.** 서버는 “누가 누구를 따르기로 했는지”만 권위.

```
매 프레임(또는 presence.changes):
  if following && huntLead.leaderCharacterId 가 presence.others 에 있음:
    leaderGrid = that.grid
    if !autoHunt.enabled: autoHunt.enable(leaderGrid)
    else: autoHunt.moveAnchor(leaderGrid)   // auto_hunt.dart:157-162
  elif leader 없음(월드 이탈) 또는 !alive 정책:
    // 접속종료: follow 해제 권고
    // 사망: 라리엔처럼 세션 유지 시 마지막 anchor 유지 → 부활 후 others에 다시 나타나면 재추적
  candidates / attack / move 실행은 기존 _updateAutoHunt 그대로
```

**leash:** `radiusMeters`를 hunt lead의 leash로 설정(기존 1~10m clamp, `auto_hunt.dart:64-71`). 리더 HUD 슬라이더는 서버 `set_hunt_leash` + 구독 반영 후 `autoHunt.radiusMeters = …`.

**경로탐색 없음:** 기존 `pursuitTimeout` 4s / `blockDuration` 3s 재사용(`auto_hunt.dart:84-93`) — 벽 뒤 몬스터 무한 추격 방지.

**텔레포트:** 리더가 `teleport_to`(`world.rs:744+`)하면 `RemotePlayerEntity`는 distance>12면 스냅(`remote_player.dart:77-80`). follower 앵커도 다음 presence에서 점프 → `moveAnchor`로 자연 재추적. follower 본인 텔레포트는 follow 유지 시 리더 쪽으로 다시 걸어감.

**앵커 소유권 (필수 정책)**

| 모드 | 땅 클릭 / 반경 버튼 | auto hunt 토글 |
|---|---|---|
| 수동 자동사냥 | `moveAnchor(클릭)` (`action_rpg_game.dart:992-995`) | 토글 on/off |
| **추종 사냥** | 클릭 이동·`moveAnchor` **무시** 또는 “추종 중” 배너 | 토글 off = **추종 중단**(서버 `stop` + disable) |
| 수동 조작(조이스틱) | 기존 `suspended` (`auto_hunt.dart:170-171`, `action_rpg_game.dart:647-656`) — 추종 중에도 “손 떼면 재개” 가능. 장기 수동 시 follow 유지 여부는 제품 선택(권고: 유지) |

단일 컨트롤러에 `enum AnchorOwner { manual, partyFollow }`를 두어 **follow가 manual을 선점**하고, follow 종료 시에만 manual re-enable.

**사망:** `onPlayerDied`가 지금 auto hunt를 끈다(`action_rpg_game.dart:1409-1412`). 추종 모드에서는 **끄지 말고 suspended**, 리스폰 후 재개 — 라리엔 follower 사망 정책과 정합. 리더 사망은 presence `alive=false` 동안 anchor 갱신 스킵.

### 3.5 문서·보상 철학 충돌

**판정: 파티 공유 데미지/EXP/loot로 바꾸지 말 것.**

이유:
1. 서버 킬 철학이 PK와 한 세트(`world.rs:16-17`): 선점 몹 뺏으려면 사람부터.
2. 파티 EXP 분배는 “같이 때리면 보상 공유” → 태그 무력화·막타 분쟁 재도입.
3. MMORPG 수천 명 동시 접속 시 파티 eligible 반경·락 복잡도가 Zone tick 모델에 의존(라리엔 `party.md` §6) — SpacetimeDB reducer-only 구조에 비용 큼.
4. 요청 기능의 핵심은 **이동 동선 공유(추종)** 이지 보상 공유가 아님.

**문서 개정 제안 문구**

`CLAUDE.md` Multiplayer:

```markdown
- Party membership and leader-follow (auto-hunt leash) are allowed for co-travel.
- Hunting credit remains solo: first-tag owns the kill, no shared damage credit,
  no party XP split, no party loot rule. Each player earns only what they tag.
- PK remains allowed; contesting a tagged monster still means fighting its owner.
```

`GAME-DESIGN.md:781` 행:

```markdown
| 파티 (동행·추종) | ✅ 멤버십·hunt lead 추종. 보상은 솔로(선점 태그) |
| 솔로 킬 크레딧 | ✅ 파티여도 EXP/loot 비공유 |
```

## 4. 리스크 · 함정

- **문서 vs 코드 불일치:** GAME-DESIGN/구 cowork 서술은 “클라 월드 미연결”인데 `SpacetimeWorldPresence`·원격 동기화가 이미 있음. 분석·구현 시 **코드 우선**.
- **`award_kill` 파티화는 되돌리기 어렵고 PK 경제를 붕괴**시킴 — 1차 범위에서 금지.
- **view/iter/생성기 제약:** 잘못된 view 반환 타입 → `Type2` 깨진 생성 코드(`GAME-DESIGN.md:680-683`).
- **공개 표 남용:** party를 public으로 두면 전 서버 파티 그래프 노출; 비공개+view가 원칙에 맞음.
- **파일 충돌:** `action_rpg_game.dart`는 양팀 핫스팟 — 파티 블록을 파일 하단 신규 섹션으로 격리하거나 믹스인/별 컴포넌트로 빼기.
- **추종 중 사망 시 현행 `autoHunt.disable()`**가 추종을 끊어 라리엔과 불일치 — 반드시 분기.
- **리더 이탈:** `on_disconnect`가 `world_player`만 지움 → 멤버십 고아/추종 좀비; hunt session 정리 규칙 필요.
- **클라이언트 전투 권위 잔존:** 로컬 `MonsterPopulation`과 서버 `monster` 이중 구조(`GAME-DESIGN.md:796-800`). 추종은 “리더 주변으로 이동”만 보장; **같은 몹을 본다는 보장은 다른 팀 몬스터 바인딩 완료 후**.
- **치팅:** 추종 이동·공격이 클라면 가짜 좌표 가능 — 기존과 동일 위험 수준; 멤버십 위조만 서버로 차단하면 1차 수용 가능(`cowork-prompt` 원칙 5).

## 6. 불확실 · 미확인

- 파티 **최대 인원**·초대 권한(leader only vs 전원): 제품 미지정 → 초기 **leader only 초대, max 4~8** 가정 `[추측]`.
- 리더 disconnect 시 **파티 해산 vs 멤버십 유지**: 미결정. 재접속 UX 필요.
- hunt lead를 **1차 파티 MVP에 포함할지**, 멤버십+UI만 먼저 갈지 — 요청은 둘 다이나 공수상 분리 가능.
- 서버 `attack_monster`와 클라 로컬 `Enemy` 전투가 언제 단일화되는지(타팀) — 추종 중 “같이 때리기” 체감에 영향.
- SpacetimeDB view가 **다수 party_member 행을 인덱스로만** 모을 때 조인 패턴의 실제 매크로 제약 — 구현 시 `cargo`로 확인 필요(읽기 전용 분석에서 컴파일 미실행).
- `party` 표를 public으로 두면 미니맵 “파티원 색”이 쉬워지나 원칙 위반 → 비공개 view vs 최소 공개 필드는 구현 시 한 번 더 검토.
- 라리엔 `test/party_*.dart` 전 파일·`sim/party.go` 라인 단위 동등성은 일부 문서 기준; Go 서버 소스는 이번 패스에서 전부 미개봉 — 세부 레이스 조건은 `[미확인]`.
