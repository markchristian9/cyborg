- 세운 가설:
  - (1) **좌표 혼용** — 반경 판정·타원 표시가 화면 좌표와 섞여 시각/판정이 어긋난다.

## 1. 결론 요약

자동 사냥은 **컨트롤러 판단 / 게임 실행 / UI** 가 잘 분리되어 있고, 요구 동작(앵커 중심 1~10 m, 반경 안 탐색·근접 사냥, 클릭으로 앵커 이동)을 코드 수준에서 **올바르게 구현**했다.  
좌표계는 그리드 일관, `AutoHuntRangeField` 타원은 판정 반경과 일치하며, 사망·텔레포트·restart·킬·스트리밍 해제·prune 에서 상태 정리가 빠지지 않는다.  
남은 문제는 “안 돌아가는 버그”보다 **근접 전용 한계(siege/sovereign 접근 중 피격)**, **추격 중 반경 리쉬 없음**, **게임 루프·UI 통합 테스트 부재**, **서버 전투 연결 시 부하 설계** 쪽이다. 단위 테스트 29개는 상태 기계에 대해 **실효적**이다.

## 3. 상세 분석

### 3.1 아키텍처

| 층 | 역할 | 게임 객체 의존 |
|---|---|---|
| `AutoHuntController<T>` | 앵커·반경·타깃·차단·행동 판단 | 없음 (콜백만) |
| `ActionRpgGame._updateAutoHunt` | `enemies` 후보 공급, 이동/공격 실행 | Flame `Player`/`Enemy` |
| `auto_hunt_control.dart` | 토글·±1 m·바닥 타원 | `HasGameReference` |

판단/실행 분리는 테스트 가능성과 유지보수에 유리하고, 의도대로 동작한다 (`auto_hunt.dart:23-27`).

### 3.2 (1) 좌표계 일관성 — **통과**

- 사람 입력: 미터 → `metersToTiles` → 타일 (`radiusTiles`).
- 선택·해제·공격 거리: 모두 `(gridA - gridB).length` / `length2`.
- 화면 좌표는 **렌더 전용** (`gridVecToScreen` in RangeField). 판정에 `position`(픽셀)을 쓰지 않음.
- `kMetersPerTile = 1.0` 이라 “5 m = 5 타일”이 성립. 나중에 미터/타일 비를 바꾸면 UI 문구와 타일 판정이 함께 움직여야 함(지금 구조는 대응 가능).

**타원 검증 (요약)**  
그리드 원 `(r cos t, r sin t)` 를 2:1 투영하면  
`x ∝ r√2 cos(·)`, `y ∝ r√2 sin(·)` 축정렬 타원.  
코드의 `_ellipseScale = √2` 와 `kHalfTileWidth/Height` 곱은 이 결과와 같다. **표시 반경 = 판정 반경.**

### 3.3 (2) 타깃 선택·해제 — **대체로 통과, 의도적 설계 포인트 있음**

흐름:

```
enable(origin) → 매 프레임 update
  → blocklist tick
  → (suspended면 판단 중단, 상태 유지)
  → 무효 타깃 해제(사망 / 반경+0.5 이탈)
  → 없으면 앵커 최근접 픽
  → 있으면 사거리 비교 → attack | approach(+pursuit) | timeout→block
  → 없으면 drift>0.6 → returnToAnchor else idle
```

- **앵커 기준 최근접** (`auto_hunt.dart:257-261`) — “가장자리로 끌려 나감” 방지. 테스트로 고정 (`auto_hunt_test.dart:147-161`).
- **히스테리시스** — 잡기 `r`, 놓기 `r+0.5`. 경계 진동 방지. 테스트 있음.
- **pursuit 4 s / block 3 s** — 경로 탐색 부재(벽 뒤) 대응. 공격 중에는 `_pursuitTime = 0` 으로 밀림 오탐 방지.
- **`forget`** — 차단 맵 키 제거 + 타깃 해제. 스트리밍/킬/prune 에서 호출 → **차단 목록 누수 경로가 주 경로에서는 막힘**.
- `moveAnchor` 는 타깃만 비우고 `_blocked` 는 유지 (`auto_hunt.dart:157-162`). 앵커를 옮긴 직후 3초간 옛 몹을 안 고를 수 있음 — 버그라기보다 잔존 정책. 테스트 없음.
- 반경을 줄여도 **즉시 재평가하지 않음**. 다음 `_releaseTargetIfInvalid` 에서 `새 r + 0.5` 밖이면 해제. 최대 ~0.5 m 히스테리시스 안에서는 줄어든 원 밖 몹을 잠깐 유지.

**리쉬 부재 (설계 공백)**  
타깃이 살아 있고 앵커 반경(+히스테리시스) 안이면, 플레이어가 수동으로 멀리 간 뒤 손을 떼면 **반경 밖에서 타깃까지 장거리 접근**한다. `returnToAnchor` 는 **타깃이 없을 때만** 동작한다. 버그라기보다 “사냥 중 케이지”가 없는 상태.

### 3.4 (3) 게임 루프·상태 정리 — **통과 (주요 경로)**

| 이벤트 | 동작 | 근거 |
|---|---|---|
| 매 프레임 | `_updateAutoHunt` 호출 | `action_rpg_game.dart:468-469` |
| 적 처치 | `forget` | `:1199` |
| 컴포넌트 제거 | `_pruneRemoved` → `forget` | `:484-488` |
| 스트리밍 회수 | `forget` | `:760-762` |
| 사망 | `disable` + 배너 | `:1290-1327` |
| 텔레포트 | `moveAnchor(player.grid)` | `:1140-1142` |
| restart | `disable` + RangeField 재추가 | `:1391, 1420` |
| pause/resume | `pauseEngine` → update 전체 정지 → 상태 동결 후 재개 | `:1359-1373` |
| 로그아웃 | 게임 인스턴스 폐기 전제 (`requestLogout` → `onLogout`) | 명시적 `disable` 없음, **누수 실해 낮음** |

사망 시 자동 사냥을 끄는 것은 안전지대 재진입 직후 옛 앵커로 재돌입하는 것을 막는 **올바른 선택**이다.

### 3.5 (4) 입력 충돌 — **통과**

- 키보드/조이스틱: `_applyInput` → `moveInput` → `suspended` → 자동 판단 `none`. 동시에 `Player` 는 `moveInput` 이 있으면 `clearMoveTarget` (`player.dart:334-337`) → **수동 우선**.
- 자동 사냥 ON + 땅 클릭/드래그: 앵커만 이동, `player.moveTo` 호출 안 함 → 다음 프레임 자동 사냥이 새 반경에서 재개. 드래그 중 앵커가 매 이벤트마다 바뀌어 **타깃이 자주 리셋**될 수 있음(의도된 “사냥터 끌기”에 가깝고, 빠른 드래그 시 선택 스래싱 가능).
- `_steerAutoHunt` 0.3 타일 임계: 정지 몹 추격 시 `moveTo` 1회 → stuck 누적 가능 → 0.35 s 후 목표 클리어 → 다음 프레임 재설정. **stuck 이 무력화되지 않음.** 벽에 막히면 결국 4 s pursuit 타임아웃으로 차단.
- UI 버튼은 자체 `TapCallbacks` + `event.handled = true`. `ActionButton` 의 연속 발동을 쓰지 않음 (`auto_hunt_control.dart:14-16`) — 토글 플리커 방지.

### 3.6 (5) SpacetimeDB / 멀티플레이 — **현재 무해, 미래 주의**

현재:

- 전투·위치는 클라이언트 로컬. `SpacetimeGameSync` 는 **progress(레벨/XP)만** 5초 주기·레벨업 즉시.
- `onEnemyKilled` → `sync?.reportKill(...)` 는 인터페이스 기본 빈 구현. **킬 스팸 없음.**
- `tryMelee` 매 프레임 호출이어도 클라이언트 쿨로 실제 스윙 ~2.6/s.

서버 `attack_monster` / `move_to` 연결 후:

- 자동 사냥이 “의도 전송” 계층에 그대로 붙으면 **다수 AFK 클라가 동일 몹을 노리는** 부하·태그 경쟁이 생긴다.
- 설계상 킬은 선점 태그·솔로 귀속 (`GAME-DESIGN.md:710-716`, `CLAUDE.md:33-36`) 이라 파티 문제는 없고, **사냥터 점유·리스폰 경쟁** 은 커진다.
- 권고: 서버 연결 시 자동 사냥은 클라 스윙 성공 시점에만 reducer 호출; `move_to` 는 기존 상한·간격 정책을 재사용.

### 3.7 (6) 테스트 실효성 — **컨트롤러: 높음 / 통합: 없음**

검증하는 것: enable/disable/toggle, 반경 clamp, 타일 환산, 반경 안밖·경계, 사망 해제, 히스테리시스, 앵커 최근접, moveAnchor, approach/attack/idle/return, suspended, pursuit timeout, block 만료, 공격 중 timeout 비적용.

검증하지 않는 것:

- `_updateAutoHunt` 가 `update` 에 묶였는지
- `faceTowards` + 부채꼴 명중
- `_steerAutoHunt` ↔ `_stuckTime` 상호작용
- `AutoHuntRangeField` √2 타원
- 스트리밍 `forget` / 사망 disable 연동
- UI 탭·레이아웃
- 원거리 몹 접근 시 생존

→ **상태 기계 회귀 방지에는 충분**, “게임이 실제로 사냥한다” 보증은 아니다. 사용자 주장의 flutter test 191 통과는 이 환경에서 실행하지 않았으므로 `[미실행 확인]` — 코드 읽기만 함.

### 3.8 (7) 게임 디자인

- **솔로 사냥 / 파티 없음**: 자동 사냥은 자기 클라의 `enemies` 만 때림. 규칙과 충돌 없음.
- **공유 월드·킬 단독 귀속**: 다수 자동 사냥이 같은 구역을 비우면 타 유저 사냥터 고갈 → MMO 경제/밀도 이슈. 기능 금지 사유는 아니고 **밸런스·정책** 이슈.
- **PK 허용**: 자동 사냥은 PC를 타깃하지 않음 → PK 자동화 아님. 양호.
- **근접 전용**: siege(7.5)·sovereign(9.0) 은 접근 중 일방적으로 맞을 수 있음. AFK 자동 사냥 시 **고레벨 구역 즉사 루프** 가능(사망 시 auto off 라 연속 재돌입은 막힘).
- `GAME-DESIGN.md` 조작표(`§11.4`)에 자동 사냥 미기재 — 문서 드리프트.

## 6. 불확실 · 미확인

- `flutter test` / `flutter analyze` 를 이 세션에서 **실행하지 않음** (읽기 전용·상태 변경 금지). 사용자 진술(29/191 통과)은 코드·테스트 내용으로만 간접 신뢰.
- 실기기에서 버튼 히트 영역과 액션 버튼 겹침·짧은 세로 해상도 레이아웃은 시각 확인 없음.
- 서버 권위 몬스터 240기와 로컬 `MonsterPopulation` 이 공존하는 전환기에서, 자동 사냥이 어느 쪽 `enemies` 를 보게 될지는 **연동 설계 이후**에 재검증 필요.
- “AFK 자동 사냥을 허용할지 / 안전지대 근처만 허용할지” 는 **기획 결정**이며 코드만으로 옳고 그름을 단정하지 않음.
- `GameSync.reportKill` 을 다른 구현체가 채울 가능성 — 워크스페이스에서는 `SpacetimeGameSync` 만 확인, 다른 서브클래스 없음(`[부분 확인]`).
