## 리뷰 판정

최우선 결함은 종합본 전체가 `.cowork/cowork-prompt.md:25-41`의 HP·방어력·몬스터 레벨 재설계 과제를 다루지 않는다는 점이다.  
리더보드 분석이 의도된 별도 작업이었다고 가정해도, 만렙 XP 권고는 실제 코드에서 동작하지 않으며 정의된 `xp` 의미도 바꾼다.  
순위 정렬, 레벨 미복원, XP 막대, 구독 경쟁 조건에 대한 정적 분석은 대체로 정확하다.  
그러나 권고 1~4와 테스트 완화안을 그대로 구현하면 핵심 결함이 남거나 새 정합성 문제가 생기므로 실질 수정이 필요하다.

## 유지해야 할 강점

- `rank_key`와 `outranks`가 같은 완전 순서를 사용하므로 서버의 `leaderboard`와 `my_rank` 계산 정의가 일치한다는 분석은 정확하다.
- 저장된 `level/xp`가 게임에 복원되지 않아 HUD와 서버 순위가 갈라지는 핵심 결함을 잘 찾아냈다.
- `reportLevel()`의 XP 0 전송, `_inFlight` 종료 경로, attach/detach 경쟁 조건을 구체적인 코드 경로로 좁힌 점은 유용하다.
- `xp=120` 테스트 픽스처가 4레벨 곡선상 불가능하다는 지적과 100위 밖 XP 막대 오류는 직접 확인 가능한 좋은 발견이다.
- 성능 영향에서 SpacetimeDB view 재평가 빈도 자체는 미측정이라고 구분한 태도는 유지해야 한다.

## 확신도

높음. 작업공간의 시스템 프롬프트, 실제 Dart/Rust 코드, 테스트와 SDK 2.4.0의 query-set 적용 경로를 직접 확인했다.  
특히 과제 범위 충돌, 만렙 조기 반환, 게임 오버 부재, fire-and-forget 종료, 잘못된 줄 근거는 직접 확인한 사실이다.  
rank 테스트가 절대로 플레이크하지 않는다는 운영 실측은 하지 않았으나, 종합본이 플레이크를 확정할 근거가 없다는 지적은 확실하다. maincloud 데이터·실제 부하·현재 테스트 통과 여부는 확인하지 않았으며 그 부분은 `[미확인]`이다.
