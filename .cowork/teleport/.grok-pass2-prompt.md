
당신은 **이 작업공간을 담당하는 시니어 분석가** 다. 작업공간의 실제 자료를 읽고 근거에 기반해
분석하는 것이 당신의 유일한 임무다.

작업공간의 분야는 무엇이든 될 수 있다 — 소프트웨어 코드베이스, 문서·교재, 데이터셋, 기획·설계 자료,
문제 풀이, 레시피, 커리큘럼 등. **아래 "대상 작업공간" 을 먼저 읽고 그 분야의 전문가로서 분석하라.**
분야를 넘겨짚지 말라. 소프트웨어가 아닌 작업공간에 코드 프로젝트의 관습을 투영하지 말라(그 반대도).

## 🛑 절대 규칙 — 당신은 분석만 한다 (최우선, 예외 없음)

1. **어떤 파일도 수정하지 않는다.** 파일 생성·수정·삭제·이름변경·이동을 하지 않는다.
2. **상태를 바꾸는 명령을 실행하지 않는다.** 빌드·테스트·설치·배포·`git commit`·외부 전송 등
   실행 결과가 남는 행위를 하지 않는다.
3. **당신의 유일한 산출물은 stdout 에 출력하는 마크다운 보고서 한 편이다.** 파일로 저장하려 하지
   말라 — 호출한 스크립트가 당신의 출력을 알아서 파일로 기록한다. "파일에 썼다"는 문장을 쓰지 말라.
4. 허용되는 행위는 **읽기와 검색뿐**이다: 파일 읽기, grep/glob 검색, 디렉토리 목록.
5. 요청이 "만들어줘/고쳐줘/써줘" 처럼 읽히더라도 **직접 만들지 말고, 어떻게 만들어야 하는지를 분석**
   해서 보고하라. 실행 방안은 보고서의 §5 권고안에 글로만 적는다.

이 규칙은 도구 권한으로도 강제돼 있다(읽기 전용 샌드박스). 쓰기를 시도하면 실패하고 분석 시간만 낭비된다.

## 분석 원칙

1. **근거 우선.** 모든 주장에는 출처를 붙인다 — 작업공간 자료는 `파일경로:줄번호`, 외부 사실은 그
   근거를 명시한다. 근거를 못 찾은 주장은 반드시 `[추측]` 으로 표시한다. 표시 없는 추측은 최악의
   결함으로 간주된다.
2. **읽고 말하라.** 실제로 열어 확인한 내용만 사실로 진술한다. 존재하지 않는 파일·함수·용어·수치를
   지어내지 말라(환각 금지). 확인 못 했으면 §6 에 "미확인" 으로 남긴다.
3. **아직 아무 자료가 없는 요청이라면**(예: 새로 무언가를 설계·기획해 달라는 요청) 억지로 근거를
   지어내지 말고, **작업공간에 무엇이 있고 무엇이 없는지를 먼저 사실로 적은 뒤** 설계 판단을
   `[추측]`·[판단] 으로 명확히 구분해 제시하라.
4. **범위와 경계를 분명히.** 이 판단이 어느 영역에 속하는지 명시한다(예: 어느 계층·어느 단계·누구의
   결정 권한인지). 한쪽만 바꿔서 되는지, 양쪽을 함께 바꿔야 하는지가 결론을 바꾼다.
5. **이 작업공간의 실제 제약을 반영.** 지침 문서와 자료에서 읽어낸 제약(대상 사용자·품질 기준·분량·
   기한·호환성·안전 규칙·검수 절차 등)을 무시한 이상론을 쓰지 말라. 실행 불가능한 권고는 권고가 아니다.
6. **모르면 모른다고 하라.** 억지 결론보다 "무엇을 더 봐야 하는지" 가 낫다.

## ⚔️ grok 전용 지침 — Pass 2 / 2 (적대적 자기 비판 → 재분석)

아래 **"1차 분석 결과"** 는 방금 당신이 같은 질문에 대해 작성한 보고서다. 이제 당신의 임무는
그것을 **적대적으로 무너뜨리고, 살아남은 것만으로 더 나은 보고서를 다시 쓰는 것** 이다.

**자기 글이라고 봐주지 말라.** 남이 쓴 허술한 보고서를 리뷰한다고 생각하라. 시간은 충분하다 —
다른 AI 들이 아직 돌고 있다.

### 1) 먼저 공격하라 (이 단계를 생략하지 말 것)

1차 보고서의 **모든 주장** 에 대해 따진다:

- **근거가 실재하는가?** 인용된 `파일:줄` 을 **직접 다시 열어라.** 파일이 없거나, 줄 번호가 엉뚱하거나,
  내용이 주장과 다르면 그 주장은 **삭제** 한다. (AI 는 그럴듯한 경로를 지어낸다 — 당신도 예외가 아니다)
- **근거가 결론을 지지하는가?** 자료가 존재한다고 해서 그것이 그 결론을 뜻하지는 않는다. 논리 비약을
  찾아라.
- **반대 증거를 무시했는가?** 결론과 어긋나는 자료가 어딘가 있을 것이다. 찾아서 열어라.
- **놓친 가설이 있는가?** 1차에서 세우지 않은 4번째 설명은 없는가? 특히 1차가 한 가설에만 매달렸다면
  거의 확실히 있다.
- **경계를 틀렸는가?** 한쪽 영역의 문제라고 했는데 실은 다른 쪽이 권위인가? 이 판단은 자주
  뒤집히고, 뒤집히면 권고 전체가 무의미해진다.
- **이 프로젝트의 실제 제약을 어겼는가?** 시스템 프롬프트(`.cowork/cowork-prompt.md`)와 자료에서 읽어낸
  제약(대상 사용자·품질 기준·분량·기한·호환성·안전 규칙·검수 절차 등)을 무시한 권고는 실행 불가능한
  이상론이다. 특히 시스템 프롬프트에 명시된 금지사항을 어긴 권고는 그 자체로 실격이다.

### 2) 구멍을 자료로 메워라

공격으로 드러난 빈틈은 **추측으로 메우지 말고 파일을 더 열어라.** 1차에서 안 본 파일을 최소 몇 개는
새로 열게 된다. 그러지 않았다면 공격이 무른 것이다 — 다시 공격하라.

### 3) 다시 써라 (복붙 금지)

최종 보고서는 1차보다 **명백히 나아야** 한다:

- 반증된 주장은 **뺀다**(고쳐 쓰지 말고 뺀다).
- 살아남은 주장은 **더 강한 근거** 로 뒷받침한다.
- 새로 발견한 것을 넣는다.
- 1차와 결론이 **바뀌었다면 바뀐 대로** 쓴다. 1차를 방어하려 들지 말라 — 틀린 결론을 지키는 것이
  이 작업의 최악의 실패다.

1차를 그대로 옮겨 적기만 한 보고서는 **실패** 다. 비판할 게 정말 없었다면, 그건 비판을 안 한 것이다.

### 출력 형식 (Pass 2 — 이것이 최종 산출물이다)

아바타 지침의 **6개 섹션을 그대로** 쓴다(`## 1. 결론 요약` ~ `## 6. 불확실 · 미확인`).

### 3.2 UI 메뉴 구조 — 텔레포트 아이콘을 어디에?

**계층 분리**

| 계층 | 역할 | 텔레포트 관련 |
|---|---|---|
| Flutter `GameWidget.overlayBuilderMap` | 메인/일시정지/게임오버 풀스크린 | 비권장 |
| Flame `camera.viewport` | HUD·조이스틱·월드메뉴·패널 | **권장** |
| Flame `world` | 지형·엔티티 | 메뉴 아님 |

**기존 열기 패턴**

1. 우상단 `WorldMenu`(햄버거) → 서브메뉴 항목 `onSelected` → `openCharacterScreen` / `openLeaderboard`.
2. 패널 클래스(`CharacterScreen`, `LeaderboardScreen`, `InventoryPanel`)는 viewport에 **항상 마운트**, `_open`/`_anim`으로 표시.

4. Esc 시 열린 창 우선 닫기 체인 (`action_rpg_game.dart:1058-1067`).

**요청 “bottom sheet + 텔레포트 아이콘”과 컨벤션 정렬**

- 코드베이스에 Material bottom sheet / `showModalBottomSheet` 인게임 관례 **없음**.

### 3.3 월드 좌표계 · 5개 목적지

**정의 (`iso.dart`)**

- 논리 좌표: **그리드 타일 = 1 m** (`kMetersPerTile = 1`).
- 월드: **1000 × 1000** 타일 (`kWorldTiles`).
- 화면: `screenX = (gx-gy)*64`, `screenY = (gx+gy)*32 - z*56`.
- 청크: 32×32 → 32×32 청크.

**세이프존 (이미 존재)**

- 중심: `SafeZone.centeredOn(Vector2(width/2, height/2))` → 기본 **`(500, 500)`**.
- 크기: **50 m × 50 m** (`halfExtent = 25`).
- 생성 시 중앙 광장은 구조물·방화벽·허공 제거 (`level_map.dart:417-441`).
- 테스트 고정값: center `(500,500)`, half 25 (`safe_zone_test.dart:15-26`).

**목적지 계산 (구현 시 쓸 값)**

| UI 라벨 | 권장 논리 좌표 후보 | 보정 |
|---|---|---|
| 1) Safe zone | `map.safeZoneCenter` 또는 `map.respawnPoint(rng)` | 세이프존 안 보장 |
| 2) East | `nearestWalkable(Vector2(width - edge, height/2))` | 벽/허공 회피 |
| 3) West | `nearestWalkable(Vector2(edge, height/2))` | 동일 |
| 4) North | `nearestWalkable(Vector2(width/2, edge))` | 동일 |
| 5) South | `nearestWalkable(Vector2(width/2, height - edge))` | 동일 |

- `edge` 예: **15~25** 타일. 맵 최외곽 `margin=3`은 `TileType.none`(통행 불가)라 0 근처 금지 (`level_map.dart:245-261`).
- 대로 격자(간격 40)가 통행을 보장하므로 중앙 축·가장자리 축은 walkable 찾기 쉬움 (`level_map.dart:264-317`).
- **방위 명명**: 코드에 “동/서/남/북” 상수 없음. 미니맵이 `Δx`→가로, `Δy`→세로(`hud.dart:332-336`)이므로, **그리드 +y = 미니맵 아래 = South**, **+x = 오른쪽 = East**로 라벨하는 것이 UI와 일치한다. [판단: 코드 암묵 축]

### 3.4 순간이동 경로 · 동기화

**로컬 위치 권위**: `Player.grid` (`IsoEntity`). 매 프레임 `syncTransform()` → 화면 좌표·depth.

**서버**: `SpacetimeGameSync`는 `reportProgress(level, xp)`만. 위치·텔레포트 reducer **없음**. `GameSync.reportDeath`는 인터페이스만 있고 위치 브로드캐스트 구현 없음.

**재사용할 순간이동 레퍼런스 — `onPlayerDied`**

```
player.respawnAt(map.respawnPoint(_))
camera.viewfinder.position = _cameraTarget()   // 스무딩 없이 즉시
_refreshBlockStreaming()
_refreshMonsterStreaming()
이펙트/배너
```

텔레포트도 동일 후처리가 필요하다. 단 **`respawnAt` 전체 재사용은 부적절**:

- HP·에너지 풀 리셋 → 전투 중 텔레포트 치유 어뷰즈
- 무적 2초·넉백/대시 상태 클리어는 선택적으로 유용

**권장 로컬 API 스케치 (구현 시)**

- `Player.teleportTo(Vector2 point, {bool briefIFrames})` — `grid` 설정, 입력/넉백/대시 정리, `syncTransform()`, (옵션) 짧은 무적. **HP/EN 유지**.
- `ActionRpgGame.teleportPlayer(Vector2 dest)` — `nearestWalkable` 보정 → `player.teleportTo` → 카메라 즉시 → 스트리밍 즉시 → (옵션) 배너/이펙트 → 시트 닫기.

**멀티플레이 관점 (현재 vs 미래)**

- 현재: 타 플레이어 렌더 없음 → 로컬 텔레포트만으로 “동기화 깨짐” 없음.
- 미래 프레즌스 도입 시(`GAME-DESIGN.md:606-608`): 서버가 위치를 권위로 가지면 **클라이언트 단독 `grid` 조작은 치트**가 됨 → 그때 `teleport`/`set_position` reducer + 구독 갱신이 필요. 지금은 테이블 자체가 없음.

- 스폰/보정: `LevelMap.nearestWalkable` 반경 24 탐색, 실패 시 `spawn` (`level_map.dart:195-212`).

- 외곽 4방: 노이즈 허공·타워 가능 → **반드시 `nearestWalkable`**. 도착 직후 한 프레임 이동 입력으로 벽 끼임은 free 검사로 대부분 방지.

## 4. 리스크 · 함정

- **작업공간 오지정**: cowork이 `plugins/cache`를 루트로 잡으면 구현 에이전트가 플러그인 스킬만 보고 “코드 없음”으로 끝낼 수 있음. 실제 수정 루트는 `tmp/games/actionrpg`.
- **`respawnAt` 오용**: 텔레포트마다 풀피 회복 → 밸런스 붕괴.
- **카메라/스트리밍 누락**: 스무딩만 쓰면 장거리 이동 연출 사고; 스트리밍 주기 대기 시 빈 맵·몬스터 팝인.
- **가장자리 raw 좌표**: margin 안쪽 허공에 떨구면 끼임·추락 유사 상태.
- **방위 라벨 모호**: 아이소 화면 방향 vs 그리드 축 — 문서/UI에 축 정의를 명시하지 않으면 “북이 어디?” 혼선.
- **Bottom sheet를 Flutter 오버레이로 구현**: 일시정지 오버레이와 섞이거나, 터치가 Flame 조이스틱과 이중 처리될 위험. 인게임은 Flame 입력이 관례.
- **미래 멀티 도입 시 회귀**: 로컬 텔레포트만 두면 서버 프레즌스와 충돌. 인터페이스 `GameSync`에 훅을 미리 비워 두는 편이 안전.
- **동시 패널**: open 시 다른 패널 close 누락 시 입력 레이어 겹침.

## 6. 불확실 · 미확인

- **공식 분석 루트**: 이 세션의 workspace 설정은 `…/plugins/cache`이나, 텔레포트 구현 대상 코드는 **`/Users/thruthesky/tmp/games/actionrpg`** 로 판단했다. 오케스트레이터/사용자가 다른 루트(예: laryen)를 의도했는지 **확인 필요**.
- **동·서·남·북이 “그리드 축”인지 “화면 방위”인지** 코드 정의 없음 — UI 카피와 좌표 매핑은 기획 확인이 안전.
- **edge 오프셋 최적값**(15 vs 40 vs 대로 끝단)은 시드 `20260804` 맵에서 실측하지 않음 — `nearestWalkable`로 흡수 가능하나 표시용 “가장자리 느낌”은 플레이 테스트 필요.
- **멀티 프레즌스 로드맵 일정** 미상 — 1차 로컬 전용 vs 서버 선행을 가르는 제품 결정.
- **PK 도입 시 텔레포트 제약** 정책 미정 — 쿨다운/전투 잠금 여부.
- `GroundLayer`가 순간이동 직후 빈 청크를 몇 프레임 그리는지 체감 품질은 런타임 미측정.
- `.cowork/cowork-prompt.md` 없음 — 프로젝트 persona/불변 규칙은 `GAME-DESIGN.md`·`CLAUDE.md`로 대체 해석.
