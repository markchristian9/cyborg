## 1. 결론 요약

**지금 코드·구독 구조로는 동접 1,000 / AOI 100은 성립하지 않는다.** `GAME-SERVER.md`의 “실질 상한 수십 명” 판정은 \(5N^2\)·\(≈33N^2\) fan-out과 `monster_ai`의 \(O(\text{근처 몹}×N)\)을 근거로 **자릿수가 맞다**.  
**조건부 설계 상한**은 다음이 **동시에** 있을 때만이다: (1) 청크 기반 구독, (2) **가시 인원 상한 ≈100**(청크만으로는 집결 시 fan-out이 다시 \(N\)), (3) Pos 세로 분할, (4) AI 청크 버킷화 + no-op update 제거, (5) 좌표 보고 5Hz→약 1~2Hz(또는 의도).  
**AOI 100·전원 이동·행 180B·5Hz**의 플레이어 좌표 egress 하한은 약 **\(5×10^5\) 행/s · ~90MB/s**(페이로드). 클라이언트 1명 수신은 ~90KB/s로 가볍지만, **서버 총 egress 90MB/s는 상시 운용 비권장**. 세로 분할(~50B)+2Hz면 **~10MB/s** 구간.  
**SpacetimeDB로 끝까지 포기할 것**: 한 좌표에 1,000명 전원 상호 가시, 존 병렬로 쓰기 처리량 \(N\)배, 구독 SQL만으로 반경·LOD·컬럼 프로젝션. 문서 갱신은 구현 반영 후에 §5·§8·§9에 수치·조건을 넣는 방향이어야 한다(본 패스는 파일을 수정하지 않음).

## 3. 상세 분석

### 3.1 질문 1 — AOI 100에서 초당 행·바이트

**기호**  
- \(N=1000\) 동접, \(R=5\) Hz(이동 중·`_minStep` 이상일 때 상한), \(A=100\) “다른 플레이어 가시 상한”, \(S_{wp}≈180\) B.

**행 크기 \(S_{wp}\)** (`world_player.dart:98-119`)  
Identity + u64 + 문자열 2 + u32 + f32×2 + i32×2 + bool + i64×7 + i32×3 + u32 ≈ **고정 ~130B대 + name/kind**. 문서 180B(`GAME-SERVER.md:175`)는 자릿수로 타당. 프로토콜 프레임 미측정 → **페이로드 하한**(실측 +10~30% 가능).

**쓰기(구독과 독립)**  
\[
U = N×R = 5{,}000\ \text{updates/s}\quad(\text{전원 매 주기 이동 최악})
\]
실무에서는 `_minStep`·정지·`_inFlight`(RTT 동안 보고 차단, `spacetime_world_presence.dart:121-144`)로 \(U\)가 더 작아질 수 있다.

| 모델 | 행/s | 바이트/s (×180B) | 판정 |
|---|---:|---:|---|
| **A. 현행 전역 구독** \(U×N=5N^2\) | \(5×10^6\) | ~900 MB/s | **불가** (`GAME-SERVER.md:186-190`와 일치) |
| **B. 가시 상한 \(A=100\) 강제** \(U×A\) | \(5×10^5\) | ~90 MB/s | **경계·상시 비권장** |
| **C. B + Pos~50B + 2Hz** | \(2×10^5\) | ~10 MB/s | **단일 인스턴스 현실 목표 구간** |
| 클라 1명 수신 \(A×R×S\) | — | ~90 KB/s @B | **가능** |

**치명적 구분(1차 수정)**  
청크 `WHERE chunk IN (9칸)`만 걸면 fan-out은 **그 공간을 구독 중인 인원**이지 \(A=100\)이 아니다. 보스 집결로 9청크 안에 1,000명이 있으면 fan-out≈\(N\) → 다시 **~900MB/s**.  
따라서 표의 **B·C는 “구독·표시·(가능하면 서버) 가시 상한 100”을 설계 규격으로 둔 경우**의 수치다. 공간 AOI만으로는 목표 대역을 보장하지 못한다.

**몬스터(같은 제약)**  
전역: \(≈33N^2\) (`GAME-SERVER.md:200-205`).  
청크 구독 + 집결 클러스터 \(C\)명, 활성 이동 몹 \(M_m\), 틱 3.33Hz, \(S_m≈90\)B 이면 클러스터 egress ≈ \(M_m×3.33×C×S_m\).  
예: \(M_m=30, C=100\) → ~0.9MB/s/클러스터. 전역 구독을 남기면 문서의 N=100·~30MB/s급이 재발.

### 3.2 질문 2 — 구독 SQL 안 AOI 구현

**제약** (`GAME-SERVER.md:91-106`): `SELECT *` only → 세로 분할이 대역 해법; 산술/반경 필터 부적합; JOIN≤2·양측 인덱스.

**코드 갭**  
- 플레이어: chunk 없음 → `WHERE chunk=` 구독 불가(`world.rs:267-359`).  
- 몬스터: `by_chunk` 있으나 **home 고정**(`world.rs:414-418`). roam≤26 < 청크 32라 AI 누락은 완화되나, **구독 AOI의 “현재 위치”와 어긋날 여지**는 남음.  
- 클라이언트: `kWorldSubscriptions` 전역 고정(`cyborg_connection.dart:39-43`).

**주력 구현: 클라이언트 나열 청크 구독** (`GAME-SERVER.md:300-310`)

```sql
SELECT * FROM world_player_pos WHERE chunk = c0 OR ... -- 최대 9
SELECT * FROM monster_pos WHERE chunk = ...
```

| 구독 청크 \(C_s\) | 9칸 커버(타일) | 보행 3.6타일/s 직선 경계 주기 | 비고 |
|---:|---:|---:|---|
| 32 (AI와 동일) | 96×96 | \(32/3.6≈8.9\)s | 재구독 잦음·진동 위험 |
| 64 | 192×192 | ≈17.8s | 균형 후보 |
| 128 | 384×384 | ≈35.6s | 스냅샷 커짐 |

재구독 1회 ≈ **신규 청크 스냅샷 행 수 × 행 크기**(겹침 zero-copy, 문서 “subscribe before unsubscribe”).  
예: 신규 1청크 플레이어 20+몹 40, pos 50B → ~3KB + 적용 1 RTT.  
**권고**: AI 청크 32와 **구독 청크 64~128 컬럼 분리** + 경계 **히스테리시스**(`GAME-SERVER.md:310`).

**RLS vs View**

| 방식 | AOI | 근거 |
|---|---|---|
| 청크 OR 나열 | **주력** | 인덱스·공유 region·서버 per-user 최소 |
| Anonymous View | **부적합** | 파라미터 없음, “내 주변” 불가(`GAME-SERVER.md:320-324`) |
| 사용자별 View | 가능·비쌈 | N배 계산 |
| RLS `:sender` | 보안 보조 | experimental, per-user 비용(`GAME-SERVER.md:312-318`) |

**보안·원칙**  
`lib.rs:15-16`은 테이블 비공개를 원칙으로 하나, `world_player`/`monster`/`monster_kill`은 **public**. 치트 클라이언트가 `SELECT * FROM world_player`를 걸 수 있다. 장기적으로 private + 청크 뷰/필터(또는 RLS) 봉인이 원칙과 맞다. 단기 AOI는 청크 구독으로 대역을 줄이되, **전역 SQL을 막는 것은 별 과제**.

### 3.3 질문 3 — 전역 락 · 5,000 TPS · 배칭

**사실**  
- 단일 writer(`GAME-SERVER.md:59-61`).  
- `move_to` 본체는 가벼움(`world.rs:1044-1085`).  
- 벤치 “~30만 TPS”는 **짧은 트랜잭션 참고치**이며 MMORPG 틱·대규모 fan-out과 동일하지 않음(`GAME-SERVER.md:352`).

**예산 스케치(추정)**  
- AI 주기 300ms. 락 점유 \(T_{ai}\) ms.  
- 창 300ms에 평균 \(0.3×5000=1500\)건 `move_to`.  
- \(T_{ai}=50\) → 잔여 250ms/1500 ≈ **0.17ms/건** 예산.  
- \(T_{ai}\)가 커지면 큐잉으로 체감 지연 폭증.  
- **현재 AI는 N과 함께 폭주**(`world.rs:1479-1487`) → N=1000에서 “5k TPS alone 가능 / **AI·대량 fan-out 동시에는 불가**”가 정확한 표현.  
- 구독 매칭·직렬화가 writer 임계구역에 포함되는 비율은 **미실측** → §6.

| R (Hz) | N=1000 move TPS 상한 | 비고 |
|---:|---:|---|
| 5 | 5,000 | 현재 클라 상한 |
| 2 | 2,000 | 보간은 0.2s 전제라 파라미터 조정 필요(`remote_player.dart:83-86`) |
| 1 | 1,000 | 의도 전송 없을 때 하한 후보 |
| 의도(출발+속도+t0) | 경로 변경 시만 | 직선 구간 TPS ≪1 |

**배칭**  
- **다수 플레이어 → 한 클라이언트 리듀서**: `ctx.sender()` 바인딩으로 **불가**(`world.rs:1694-1700`).  
- **한 플레이어 waypoints[] 한 호출**: 가능, 호출 TPS↓.  
- **입력 큐 테이블 + scheduled reducer가 여러 행 update**: 트랜잭션 경계 감소 이득 가능하나, **행 update·fan-out 총량은 남음**. “5,000 클라 호출을 공짜로 1회로”는 불가.

### 3.4 질문 4 — `monster_ai` 자료구조

**현재** (`world.rs:1428-1587`)  
1. 생존 플레이어 전체 Vec — \(O(N)\)  
2. 플레이어당 9청크 `by_chunk` — 근처 몹 집합  
3. 각 근처 몹 × **전체** 플레이어 최근접 — \(O(M_{\text{near}}×N)\)  
4. 주석 “사람 수는 적으므로 전부 재도 싸다”(`world.rs:1480`) — N=1000에서 **거짓**.

문서: N=1000·\(M_{\text{near}}→7500\)이면 틱당 7.5M 거리, 초당 ~2.5×10⁷(`GAME-SERVER.md:222-226`).  
(산개해 전 청크를 덮을 때 상한; **한점 집결**이면 \(M_{\text{near}}\)는 줄지만 \(×N\)은 남음.)

**모듈 메모리 상주 인덱스 불가**(`GAME-SERVER.md:80-88`) → **틱 로컬만**:

```text
by_chunk: HashMap<u32, Vec<&WorldPlayer>>  // O(N) 구축
활성 몹 = 사람 있는 청크∪이웃의 by_chunk
각 몹: 자기+이웃 청크의 플레이어만 순회
```

**재구축 포함 비용**  
- 맵 구축 \(O(N)\): N=1000이면 μs~0.1ms급 `[추측]`.  
- 거리: \(O(M_{\text{active}}×P_{\text{local}})\).  
  - 산개: \(P_{\text{local}}≈1~5\) → 틱당 수천~수만.  
  - 목표 집결 A=100: \(P_{\text{local}}≈100\), \(M≈100~300\) → \(10^4~3×10^4\) ≪ 7.5×10⁶.  
  - **전원 9청크 안 1000명**: 여전히 \(M×1000\). 표시 AOI 100과 별개로 **AI는 전원 반응** → 핫스팟 상한·원거리 AI 저주파 필요.  
- 무인 청크 스킵·**이동 없는 몹 update 금지**(regen 원칙, `world.rs:1615-1616`).

### 3.5 질문 5 — 기법별 절감(수치 비교)

기준 \(B_0\): **가시 상한 100 + N=1000 + 5Hz + 180B** → \(5×10^5×180 ≈ 90\) MB/s.  
(전역 900MB/s 대비 AOI 상한은 **÷10**이지만, 상한 없이 청크만이면 집결 시 ÷1.)

| 기법 | 가정 | 대략 결과 | \(B_0\) 대비 |
|---|---|---|---:|
| 전역→가시 상한 A=100 | fan-out N→A | 900→90 MB/s | **÷10** (전역 대비) |
| 세로 분할 Pos | 행 ~50B (id+xy+chunk+ts) | 90→**~25** MB/s | **÷3.6** |
| f32→고정밀 축소 | xy 8B→4B 등 | 분할 후 **~10%대** | 작음; **i16 타일 정수만**이면 보간 품질↓, 월드 1km 서브타일을 i16 한 칸에 넣으려면 스케일 설계 필수 |
| 의도 전송 | 방향 유지 시 0.2~1Hz | 5Hz→0.5Hz면 **÷10** | 경로 재계산 잦으면 이득↓; 몹에 더 적합 |
| LOD 쓰기(근 20@5Hz, 원 80@1Hz) | \(R_{avg}=1.8\) | **÷~2.8** | **구독 SQL만으로 불가** — 서버가 먼 행을 덜 update해야 함 |
| 보고 2Hz | R=2 | 행 수 ÷2.5 | **÷2.5** |
| **조합** 상한100+분할+2Hz | \(1000×2×100×50\) | **~10 MB/s** | 운용 목표 |
| +의도/LOD | 실효 R~1 | **수 MB/s** | 목표 여유 |

### 3.6 질문 6 — 변경 우선순위 · “끝내 불가”

| 순위 | 변경 | 예상 효과 | 조건 |
|---:|---|---|---|
| 1 | 전역 구독 제거 + `WorldPlayer` chunk(+index) + 9청크 구독 | 산개 시 egress를 N 비의존으로; 집결은 **별도 상한** 없으면 회귀 | **필수** |
| 2 | **가시/표시 상한 ≈100**(클라 필터 + 가능하면 서버) | 집결 최악을 \(A\)에 고정 | 기획 합의 |
| 3 | Pos/Vitals/Meta 세로 분할 | 좌표 행 **÷3~4** | `SELECT *` 대응 |
| 4 | `monster_ai` 청크 버킷 + no-op update 제거 | AI CPU **÷10~100**(분포 의존) | 전역 락 예산 회복 |
| 5 | 보고 5Hz→2Hz(또는 의도) | TPS·egress **÷2.5~10** | `RemotePlayerEntity` 보간 재조정 |
| 6 | 구독 청크 64~128 + 히스테리시스 | 재구독 **÷2~4** | AI 청크와 분리 |
| 7 | CombatEvent 분리(지연 삭제) | 연출 대역; 동일 트랜잭션 insert+delete 함정 회피(`GAME-SERVER.md:280`) | deaths 카운터와 역할 분리 |

**끝내 타협**  
1. 단일 DB·무수평 확장(`GAME-SERVER.md:71-76`).  
2. 쓰기 전역 직렬화 → 존 병렬로 처리량 \(N\)배 불가.  
3. 구독으로 “반경 R”·컬럼 일부·주파수 LOD 표현 불가.  
4. 상주 spatial hash 불가 → 매 틱 재구축 또는 테이블 인덱스.  
5. **AOI≈999(전원 상호 가시 1,000) 불가** — 네트워크·락 동시 한계.  
6. 미측정 “1,000 가능” 단정 불가 — 봇 부하 테스트 필수(`GAME-SERVER.md:341-350`).

**목표 달성 정의**  
- **가능 구간**: 동접 1,000(산개·다지역) + **지역 가시 ≤100** + 위 1~5 + AI p95 \(T_{ai}<50\)ms급 + 총 egress 수 MB/s대.  
- **불가 구간**: 한 점 1,000 전원 5Hz·전체 행 전역 구독.

## 4. 리스크 · 함정

- **문서 vs 코드**: `GAME-SERVER.md`는 AOI·분할·AI 수정을 권고하지만 코드는 전역 구독·chunk 없는 `WorldPlayer`·\(O(M×N)\) 루프. 문서만 읽고 “이미 설계됨”으로 오해하기 쉬움.  
- **청크 구독 ≠ AOI 100**: 인원 상한 없이 집결하면 \(5N^2\) 회귀.  
- **`lib.rs` 비공개 원칙 vs public 월드 테이블**: 치트 전역 구독·원칙 문서 불일치.  
- **재구독 깜빡임**: unsubscribe 선행 시 공백 → subscribe 먼저(`GAME-SERVER.md:308-309`).  
- **home-chunk 몬스터** vs 현재 좌표 구독 오차(roam 26).  
- **변화 없는 update** = 전 구독자 스팸; move/AI에도 regen과 같은 원칙 필요.  
- **이벤트 insert+delete 동일 트랜잭션** 미전달(`GAME-SERVER.md:280`).  
- **Maincloud egress 과금**: 90MB/s는 기술·비용 동시 문제(`GAME-SERVER.md:192`).  
- **측정 부재**: 180B·AI ms·실 TPS는 추정; 자릿수 안정, 계수 ±2배 가능.  
- **제품 코멘트 충돌**: `spacetime_world_presence.dart:13-15`는 “모든 접속자 좌표가 온다”를 전제로 서술 — AOI 전환 시 의도적 제품 변경.  
- **`.cowork/cowork-prompt.md`**: “멀티플레이 동기화 없음·몬스터 레벨 없음” 등 **구식**; 실제 코드·`GAME-SERVER.md`가 진실.  
- **문서 업데이트 요청**: 읽기 전용 분석이므로 파일 미수정; 반영 위치만 §5.

## 6. 불확실 · 미확인

- BSATN+WebSocket 프레임 포함 **실측 바이트/행**; Identity 실제 인코딩 길이.  
- `move_to` p50/p99 ms; `monster_ai` 벽시계 @ N=10/100/1000.  
- fan-out·구독 매칭이 **write lock 안/밖** 중 어디서 CPU를 쓰는지.  
- Maincloud 플랜별 egress·CPU 한도.  
- 목표 “AOI 100”이 **최악 집결 스펙**인지 **평균**인지 기획 미확인.  
- 실제 이동 비율(정지·`_minStep`·`_inFlight`) — 5Hz 전제 대비 실트래픽.  
- 구독 쿼리당 OR 청크 개수 하드 캡.  
- RLS 안정화 시점.  
- BitCraft 부하 프로파일과의 유사성 미검증.

**결정적 실험**  
1. N=100 전역 구독 egress → \(5N^2×S\) 검증.  
2. 동일 N에서 AI 틱 시간만 프로브 → 락 점유.  
3. 청크 구독 프로토타입 후, **집결 1000(상한 없음)** vs **가시 100**에서 egress가 \(N\)이 아니라 \(A\)에 묶이는지 확인.

## 7. 자기 비판으로 바로잡은 것

- ❌ **철회/약화**: “AOI 구독만으로 fan-out이 A=100으로 고정되어 90MB/s” — 청크 SQL은 **공간 필터**일 뿐(`GAME-SERVER.md:300-310`). 9청크 안 1,000명이면 fan-out≈\(N\)으로 **900MB/s 회귀**. 90MB/s는 **가시 상한 100을 강제할 때만** 성립.  
- 🔁 **수정**: “5,000 TPS `move_to`는 단순 리듀세라 이론상 가능” → **AI·대규모 fan-out·구독 매칭과 분리하지 않으면 성립하지 않음**. 벤치 ~30만 TPS는 단순 트랜잭션 참고치(`GAME-SERVER.md:352`). “alone / with AI+fan-out” 이원 표현으로 교체.  
- 🔁 **수정**: f32→i16 “추가 ~10% 절감”을 일반 해법처럼 서술 → 월드 1km·서브타일 전제에서 i16 스케일은 **양자화 설계 없이는 품질 손실**; 절감은 분할 후 부차적.  
- 🔁 **수정**: LEASH/ROAM 혼동 여지 — leash **16**, max roam **26**(`world.rs:145-152`); home-chunk 정당화는 roam 26 기준이 맞음.  
- ➕ **추가**: `_inFlight`로 실효 보고율 ≤ min(5Hz, ~1/RTT) (`spacetime_world_presence.dart:121-144`) — 실 TPS는 5k 미만일 수 있음.  
- ➕ **추가**: `lib.rs:15-16` “모든 테이블 비공개” vs `world_player`/`monster` **public**(`world.rs:267-368`) — 치트 전역 구독·원칙 불일치.  
- ➕ **추가**: `monster_ai` 주석 “by_grid_x”(`world.rs:1426`)와 실제 `by_chunk` 불일치; “사람 수 적어 전부 재도 싸다”(`world.rs:1480`)는 N=1000에서 반증.  
- ➕ **추가**: `.cowork/cowork-prompt.md`는 멀티플레이·몬스터 레벨 부재 등 **구식**; 본 분석 기준은 실제 코드 + `GAME-SERVER.md`.  
- ➕ **추가**: 제품 코멘트 “모든 접속자 좌표가 온다”(`spacetime_world_presence.dart:13-15`)와 AOI 목표의 **의도 충돌** — 구현 전 기획 합의 필요.  
- 🔁 **유지(강화 근거)**: 현행 전역 \(5N^2\)·AI \(O(M×N)\)·chunk 없는 플레이어·sender 고정 배칭 불가는 줄 번호 재검증으로 **생존**. 목표 달성 패키지에 **가시 상한**을 1순위급으로 격상.
