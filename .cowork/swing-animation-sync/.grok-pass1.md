  1. **데이터 경로 부재** — 서버에 공격 사건 필드가 없거나 구독/매핑이 안 되어 남의 화면에 스윙이 아예 없다.
  2. **클라이언트 재생 가드 버그** — `last_attack_at` 은 오지만 `RemotePlayerEntity` 가 “첫 스냅샷 스킵” 로직 때문에 재생을 놓친다.

## 1. 결론 요약

**멀티플레이어 골격(위치·방향·HP·몬스터·루트·공격 사건 필드)은 이미 서버 권위로 깔려 있고, “칼 휘두름이 남에게 전혀 설계되지 않았다”는 말은 코드와 맞지 않는다.**  
다만 **원격 스윙 재생 가드가 첫 타를 삼키는 버그**가 있고, **로컬 칼 궤적 대비 원격 연출이 훨씬 약하며**, **서버에 남는 것은 “성공한 타격”뿐**이라 빗나간 스윙·서버 거절 스윙은 남 화면에 영원히 없다.  
그래서 체감은 “내 화면만 휘두른다”에 가깝게 나온다. 수정은 (1) 재생 prime 분리, (2) 로컬과 동급 슬래시 연출, (3) 필요 시 스윙 의도/성공 분리 중 선택, (4) 대시·사망 등 잔여 비동기 연출 보강 순이 맞다.

## 3. 상세 분석

### 3.1 질문의 범위

요청은 **“서버/다인 화면 동기화가 되는지 + 특히 PC 근접 스윙이 남에게 안 보이는 문제”** 다. (주입 프롬프트의 HP 1만·방어력 재설계와는 별 축. 다만 현재 코드에는 이미 `baseMaxHp = 10000` 등이 반영된 상태다 — `player.dart:46-48`.)

권위 경계:

| 축 | 권위 | 화면 연출 |
|---|---|---|
| 위치·facing | 서버 `move_to` | 원격 보간 |
| 몹 HP·생사·선점 | 서버 | `Enemy.applyServerState` |
| 내 HP/MP/사망 누계 | 서버 | `_adoptServerState` |
| **근접/스킬 타격 성공** | 서버 reducer | 원격: `last_attack_at` 변화 → 스윙 |
| **로컬 스윙 애니메이션** | 클라이언트 즉시 | **내 화면만** `Player` |
| 대시·버프 오라 | 로컬만 | 원격 미반영 |

### 3.2 의도된 공격 동기화 파이프라인 (정상 설계)

```text
A: tryMelee → (로컬 스윙 즉시)
   → progress 0.35 히트 → Enemy.applyDamage(server)
   → presence.attack(id)
   → attack_monster 성공
   → WorldPlayer.last_attack_at / attack_dir 갱신
B: 구독 델타 → presence.others
   → RemotePlayerEntity.applySnapshot
   → lastAttackAt 변화 → _swingTimer / 호 / (plasma면 탄)
```

이 파이프라인의 **서버·표 구간**은 통합 테스트로 확인된다. 문제는 **끝단 재생·연출 동급성·사건 정의** 쪽이다.

### 3.3 핵심 결함 A — 첫 공격 스킵 (재생 가드)

`RemotePlayerEntity.applySnapshot` (`remote_player.dart:180-206`):

- 의도: 시야 진입 시 **과거** `last_attack_at` 을 재생하지 않기.
- 구현: `_playedAttackAt == 0` 이면 재생 안 함.
- 부작용: 한 번도 안 친 요원은 서버 값이 계속 `0`(epoch). 그 상태에서 **첫 실제 공격**이 `0 → T1` 으로 올 때도 `_playedAttackAt` 이 아직 `0` 이라 **재생이 스킵**되고, `T1` 만 기록된다. **두 번째 타부터** 보인다.

몬스터 타격 연출(`enemy.dart:173-177`)도 같은 패턴이다.

시야에 들어온 직후 한두 대만 보는 관찰자·단타 위주 플레이에서는 “남의 스윙이 없다”로 읽히기 충분하다.

### 3.4 핵심 결함 B — 로컬 vs 원격 연출 격차

| | 로컬 `Player` | 원격 `RemotePlayerEntity` |
|---|---|---|
| 칼 궤적 | 긴 호 + 칼날 라인, 콤보별 방향 | 짧은 `drawArc` 한 번 |
| 칼 표시 | 항상(기본 `showBlade`) + 스윙 궤적 | 스윙 중만 **등 칼** |
| 팔 | melee 시 armSwing 0, 궤적이 주역 | armSwing 윈드업/스트라이크 |
| 길이 | 0.32s 상태 | 0.26s 타이머 |
| 사운드/히트스파크 | 있음 | 스윙 사운드 없음(plasma 탄 소리만) |

멀리서 보면 원격 스윙이 **걷기와 구분 안 되는 수준**일 수 있다. 데이터는 와도 “안 보인다” 보고와 양립한다.

### 3.5 핵심 결함 C — 사건 정의가 “성공 타격”뿐

- 로컬 스윙: 대상 없어도·빗나가도 애니메이션·스윙음 (`tryMelee`).
- 서버 기록: `attack_monster` **성공 후**에만 (`world.rs:1553+`).
- 로컬 히트 판정은 됐는데 서버가 좌표 불일치·쿨다운으로 거절하면: 내 화면은 스윙+피격음, 남 화면은 스윙도 몹 HP 변화도 없음 (`enemy.dart:600-603` 은 거절 여부를 기다리지 않음).

예측 좌표와 서버 좌표 어긋남(`player.dart:852-876` reconcile)이 잦을수록 이 갈라짐이 늘어난다.

### 3.6 멀티 동기화 전반 — 되는 것 / 빠진 것

**대체로 되는 것**

- 입장·청크 구독·재구독 히스테리시스 (`spacetime_world_presence.dart`)
- 20 Hz 위치·facing 보고와 원격 보간
- 서버 몹 스트리밍·HP·사망 연출·선점 표시
- 루트·줍기
- 플라즈마: 원격에 0 데미지 탄 연출 (`remote_player.dart:200-203`)
- 내 피격/사망 연출 (`lastDamagedAt`·`deaths`)
- 파티·리더보드(별 경로)

**약하거나 없는 것**

1. 원격 근접 스윙 — 위 A·B·C  
2. **대시** — 서버 필드 없음, 원격 잔상 없음  
3. **원격 사망** — `alive` 가 false로 남는 구간이 거의 없고 `deaths` 미전달 → 순간이동/청크 이동으로만 보임  
4. 버프 오라·콤보 단계·로컬 히트스파크의 관찰자 공유  
5. 오프라인/`OfflineWorldPresence` 에서는 `others` 비어 멀티 자체가 없음(의도)

### 3.7 문서 vs 코드

- `lib.rs` 머리말 “모든 테이블 비공개” vs `WorldPlayer`/`Monster` public — MMORPG 월드 표는 공개가 실측 설계.
- cowork Overview “실시간 멀티 없음” 은 **구식**; 현재는 서버 판정 전투 단계.

## 4. 리스크 · 함정

- **가드 “수정” 시 회귀**: prime 없이 `_playedAttackAt != 0` 만 지우면, 시야 진입 시 과거 공격 시각으로 **등장 직후 헛스윙**이 다시 난다. `bool _attackPrimed` 분리가 안전하다.
- **연출만 키우고 데이터 버그 방치** 하면 첫 타·거절 타는 여전히 안 맞는다.
- **모든 스윙을 서버 사건으로** 만들면 트래픽·쿨다운 의미·치트(허공 연타로 연출 스팸) 이슈. 권고는 “성공 타격 연출 강화 + 선택적 의도 이벤트” 단계.
- **클라이언트 신뢰 원칙**: 연출용 탄 `damage: 0` 유지(`remote_player.dart:296-297`). 관찰자 화면에서 피해를 넣지 말 것.
- **테스트 공백**: 표 동기화 통과 ≠ 스윙 보임. `RemotePlayerEntity` 단위 테스트가 없으면 같은 회귀가 재발한다.
- **AOI**: 서로 다른 플레이어 청크면 행 자체가 없어 “동기화 버그”로 오진하기 쉽다.

5. 배포 시 `spacetime publish` + 생성 코드 재생성 규칙 준수

## 6. 불확실 · 미확인

- **실기기 2인 화면**에서 첫 타 스킵이 사용자 증상의 주원인인지, 연출 빈약함이 주원인인지는 런타임 재현 없이 비율 단정 불가. 코드상 **둘 다 실재**한다.
- maincloud 배포 스키마가 로컬 `world.rs` 와 100% 동일한지(옛 모듈이면 필드 누락) — 이 샌드박스에서 publish/실접속 검증 안 함. 통합 테스트가 통과하는 환경이라면 배포본에 필드는 있다.
- SpacetimeDB `Timestamp` → Dart `Int64.toInt()` 정밀도/비교 이슈는 네이티브에서 보통 문제 없으나, 웹 타깃이 있다면 `[추측]` 추가 확인 필요.
- 사용자가 본 장면이 **AOI 밖·오프라인 모드·한 명만 온라인** 이었는지 로그/HUD `AGENTS` 수로 교차 확인 필요(`hud.dart` presence 표시).
- 대시·스킬 전체 목록·파티 팔로우 중 공격 가시성은 이번 깊이에서 전수 추적하지 않음 — 스윙 이슈와 분리 가능.
