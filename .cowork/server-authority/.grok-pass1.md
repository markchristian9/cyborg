## 1. 결론 요약

**상태 동기화·서버 판정 전투의 뼈대는 이미 동작한다.** 다른 PC 이동/방향/공격 스윙 힌트, 서버 몬스터 위치·HP·선점, 전리품, 내 HP/MP/사망 누계는 SpacetimeDB 공개 표 구독으로 공유된다.  
**그러나 “여러 화면에 동일한 애니메이션·발사체·스킬 궤적·몬스터 공격 연출”은 성립하지 않는다.** 사건은 별도 이벤트 스트림이 아니라 상태 델타(`last_attack_at`, HP, `deaths`)로만 전달되며, 클라 연출 계층이 그중 일부만 재생한다.  
**수정 우선순위는 (1) 서버 몹 사망/피격 연출·시체 처리, (2) 서버 XP→내 캐릭터 UI 반영, (3) PK 입력 배선, (4) 온라인에서 로컬 피해/사망 경로 격리, (5) 원격 스킬·몹 공격 연출 보강**이다. 문서는 코드보다 뒤처져 있어 판단을 흐린다.

## 3. 상세 분석

### 3.1 무엇이 “진실”인가 (권위 경계)

| 축 | 권위 | 경로 |
|---|---|---|
| 다른 PC 좌표·facing | 서버 `WorldPlayer` (클라 보고 + 속도 상한) | `move_to` ← `presence.report` |
| 몬스터 좌표·HP·생사·태그 | 서버 `Monster` + `monster_ai` | 구독 → `ServerMonster` → `Enemy.applyServerState` |
| 플레이어→몹 피해 | 서버 reducer | `attack_monster` / `cast_skill` |
| 몹→플레이어 피해 | 서버 `monster_ai` + `apply_damage_to_player` | HP 델타 구독 |
| PK | 서버 `attack_player` | **클라 UI/입력 미연결** |
| 전리품 | 서버 `Loot` + `pick_loot` | `_syncServerLoot` |
| 성장 XP(서버 전투) | 서버 `award_kill` → `PlayerCharacter.total_xp` | 클라 HUD 반영 **끊김** |
| 성장 XP(신고) | 클라 `report_progress` | 리더보드/캐릭터 표 (조작 여지) |
| 발사체 궤적·스킬 VFX | **로컬 전용** | 공유 안 됨 |
| 이동 보간 | 클라 | `RemotePlayerEntity` / `Enemy._followServer` |

설계 원칙(`lib.rs` 머리말)과 맞게 소유자·판정은 `ctx.sender()` 쪽이다. 다만 **이동은 완전 서버 시뮬이 아니라 클라 좌표 + 속도 캡** (`world.rs:1312-1316`, `MAX_MOVE_SPEED=14`).

### 3.2 잘 되는 것 (다수 화면 공유)

1. **다른 PC 존재·이동·방향**  
   청크 구독 + 200ms `move_to` + 보간. 통합 테스트가 “서로를 본다”, “제자리 회전”, “공격 시각 공유”를 검증.

2. **몬스터 공유 상태**  
   온라인 몹은 `serverId` 부여, 로컬 AI 비활성, HP/위치는 서버 스냅샷. A가 깎은 HP를 B가 보는 계약이 코드·테스트에 존재.

3. **내 전투 결과의 서버 확정**  
   평타/스킬은 “의도만 전송”. 연출 탄이 서버 몹에 닿아도 `isServerJudged`로 재공격하지 않음 (회귀 테스트 존재).

4. **사망 사건(플레이어)**  
   `alive` 찰나를 믿지 않고 `deaths` 증가로 연출 (`_onServerDeath`). GAME-SERVER §6.5의 “insert-delete 이벤트 함정”을 피하는 방식.

5. **AOI**  
   면적 기반 3×3 + 표시 상한 50(PC/몹). 인원 상한 SQL 불가라는 플랫폼 제약을 올바르게 우회.

### 3.3 깨지거나 빈 것 (요청하신 “애니메이션/이벤트 공유”)

#### A. 원격 PC 전투 연출이 불완전

- 공유되는 것: 스윙 타이밍(`last_attack_at`), 방향, 스킬 코드(0=평타, 1=plasma), HP 바.
- 공유 안 되는 것:
  - **플라즈마 볼트 비행 궤적** — 공격자 클라만 `spawnProjectile`. 관찰자는 스윙 호 색만 바뀜 (`remote_player.dart:280-283`).
  - 히트 스파크/카메라 쉐이크/콤보 단계 등 로컬 전용 FX.
- 결과: “A가 쏘는 레이저를 B 화면도 같은 궤적으로 본다” **미구현**. 설계상 의도(서버 즉시 판정)와 연출 요구가 충돌.

#### B. 몬스터 이동은 공유, 몬스터 공격 연출은 없음

- 서버 구동 몹 `update`는 `_followServer`만 → `phase`는 idle/chase 추정. telegraph/strike/발사 없음.
- 실제 피해는 서버가 HP만 깎음. 관찰자·본인 모두 **몹이 때리는 모션/적 탄막 없이 HP만 줄어듦**.
- 피격 숫자(`DamageText`)는 `Player.applyDamage`에만 있음. `adoptServerVitals`는 HP를 조용히 덮어씀 → **서버 피격 시 데미지 팝업·히트스톱이 안 뜰 수 있음**.

#### C. 서버 몹 사망 연출 단절 (중요 버그 후보)

- 로컬 `_die()`만 `Explosion` + `onEnemyKilled` + `removeFromParent` (`enemy.dart:583-600`).
- `applyServerState(alive:false)`는 플래그만 바꿈. **`_die()` 호출 없음**.
- `render`는 `isAlive`를 보지 않고 본체를 계속 그림 (`enemy.dart:606+`).
- `_refreshMonsterStreaming`은 죽은 스냅샷에도 기존 엔티티를 갱신만 함 (새로 만들 때만 skip).
- 결과: 서버 몹이 죽어도 **폭발 없이 서 있는 시체**, 킬 카운트/점수 미반영, 자동사냥 `forget` 지연 가능. 리스폰(20초)까지 잔존.

#### D. PK는 서버만 있고 플레이 루프에 안 붙음

- `presence.attackPlayer` / reducer 존재.
- `meleeTargets()` = 적 + 파괴 가능 블록만. **RemotePlayerEntity는 Damageable도 아님**.
- 게임/UI 어디에서도 `attackPlayer` 호출 없음 (테스트·Offline stub 제외).
- 결과: 규격상 PK 허용이지만 **유저가 다른 PC를 때릴 입력 경로가 없음**.

#### E. 성장 표시 단절

- 서버 몹 처치 XP는 `award_kill`만 (`action_rpg_game.dart:1693-1700` 주석대로 로컬 `gainXp` 안 함).
- 게임 루프가 `my_characters.totalXp` 변경을 `player.restoreProgress`로 옮기는 코드 **없음**.
- `SpacetimeGameSync`는 **클라 totalXp를 서버로 밀어 올리는** 방향 (`spacetime_game_sync.dart:56-62`).
- 결과: 온라인 사냥 시 **서버/리더보드는 오르고 HUD 레벨·XP 바는 안 오를 수 있음**. 재접속 시에야 캐릭터 선택 값으로 맞춰짐 [추측: 실플레이 확인 필요, 코드 경로상 유력].

#### F. 이중 권위 잔재 (온라인)

| 경로 | 온라인 문제 |
|---|---|
| 방화벽 `_updateHazard` → `applyDamage` | 서버에 hazard 판정 없음. 로컬만 깎이다가 `adoptServerVitals`가 되돌리거나, 로컬 사망→`onPlayerDied` 후 서버와 위치 불일치 가능 |
| `onPlayerDied` vs `_onServerDeath` | 로컬 사망은 클라 리스폰, 서버 사망은 deaths 기반. 두 경로 공존 |
| 오프라인 몹/드롭 코드 | presence 없을 때만 의미가 있으나 코드 경로는 공유 |

#### G. 스킬/액션 범위

- 서버 스킬: `plasma` 하나 (`skill_spec`).
- 버프 포션·대시·로컬 콤보 등은 서버 상태 머신 밖.
- MP/HP 회복 틱은 서버 `regen_tick` + 클라 예측 (`player.dart:368-371`).

### 3.4 문서 vs 코드 (판단에 영향)

| 문서 주장 | 코드 현실 |
|---|---|
| cowork-prompt: “실시간 멀티플레이 동기화는 아직 없다” | presence·remote·server monster 동작 |
| GAME-DESIGN §13: 클라가 world 미사용, 원격 미구현, PK 미구현 | 원격·몬스터 동기화 구현됨. PK는 **서버만** |
| GAME-DESIGN: enter_world 항상 중심 | 클라 좌표 허용(안전지대 검증) `world.rs:1228-1244` |
| cowork-prompt HP 120, 몬스터 레벨 없음 | 서버 `BASE_MAX_HP=10000`, 몹 레벨 1~200, 피해=레벨 |

**분석 기준은 코드다.** 문서만 보면 “아직 안 붙였다”고 잘못 고치게 된다.

### 3.5 MMORPG 관점

- 동일 월드 다수 접속·AOI·서버 몹·선점 킬은 **골격 성립**.
- 연출 비공유는 “같은 전투를 보고 있다” 체감을 깎음 (특히 원거리 스킬·몹 탄막).
- `report_progress` 잔존 + 클라 XP 미수신은 리더보드/HUD 신뢰 문제.
- 이벤트 테이블을 쓸 경우 insert-delete 동시 트랜잭션 함정(`GAME-SERVER.md:310-318`)을 피해야 함 — 현재 `last_attack_at`/`deaths` 방식이 더 안전.

## 4. 리스크 · 함정

- **시체 잔존·사망 FX 누락**: 서버 킬 UX 핵심 결함. “몹이 안 죽는다”로 오인 가능.
- **XP HUD 고갈**: 서버만 성장, 화면은 1레벨처럼 보임 → 밸런스·자동사냥 판단 왜곡.
- **PK 미배선**: 선점 규칙이 “사람 쳐서 뺏기”를 전제하는데 실행 수단 없음.
- **이중 사망/로컬 hazard**: 온라인에서 서버 좌표와 클라 리스폰이 어긋나는 순간 발생 가능.
- **연출용 CombatEvent 도입 시**: 같은 reducer에서 insert 후 즉시 delete 하면 **구독자에게 안 감**. TTL + scheduled 삭제가 필수.
- **이동 보고 RTT 백프레셔**: `_inFlight`로 실효 5Hz 미만 → 관찰자 보간 끊김, 사거리 거절 증가.
- **표시 상한 50**: 안전지대 밀집 시 “사람/몹이 안 보인다” ≠ 서버에 없음.
- **문서 노후**: 구현자가 GAME-DESIGN §13만 보면 이미 있는 코드를 다시 짜거나 반대로 연출만 손대다 판정을 건드릴 위험.
- **보안**: 피해량 조작은 막혔으나 `move_to` 속도 캡 내 텔레포트성 이동·`report_progress` 완만 인플은 여전히 가능 (주석이 인정).

## 6. 불확실 · 미확인

- maincloud 실서버 동시 2클라 **화면** 검증은 이 세션에서 실행하지 않음. 통합 테스트는 reducer/캐시 수준.
- 서버 몹 시체가 실제로 20초 동안 그려지는지 프레임 단위 실측 미실시 (코드 경로상 유력).
- 온라인 사냥 중 HUD XP가 완전히 멈추는지 — `my_characters` 캐시 갱신 후 다른 화면이 간접 반영하는지 전수 미추적.
- `monster_ai`의 `by_chunk`(홈) vs `pos_chunk`(현재) 경계 케이스에서 추격 누락이 실측되는지.
- 파티 추종·초대와 전투 동기화 교차 시나리오 깊이 미검토.
- 클라이언트 콤보 배율(1.6) vs 서버 `player_damage` 단일값 — 화면 연출 피해와 실판정 불일치 체감 정도.
- cowork-prompt의 “HP 재설계” 요청과 본 질문(멀티 동기화)은 별 트랙; HP 10k/방어/몹레벨은 **서버에 이미 반영된 상태**로 보이나, 전 클라 상수 일치 전수는 계약 테스트 범위 밖 일부 가능.

**한 줄 판정:** 서버 권위 **상태 동기화는 동작한다.** 요청하신 **동일 애니메이션·발사체·이벤트 공유는 설계적으로 미완이며**, 그중 서버 몹 사망 연출·XP UI·PK 입력은 “보완”이 아니라 **빠진 배선**에 가깝다. (이 분석 패스는 읽기 전용 — 수정은 하지 않았다.)
