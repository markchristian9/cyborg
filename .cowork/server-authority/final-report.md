# final-report — server-authority

> 요청: 서버 판정·서버 권위 이동·클라이언트 보간·PC별 이벤트/액션/스킬/타격/사망/HP/MP 공유가
> 올바로 동작하는지 확인하고 수정·보완. 특히 여러 플레이어 화면에 **다른 PC 이동·몬스터 이동·
> 스킬 사용·공격·피격·사망·공격 모션·스킬 애니메이션·총알/레이저/미사일 궤적**이 동일하게
> 보이는지.
>
> 분석: codex · grok(2-pass) · kimi — **claude 는 두 번 모두 실패**(1차는 계획만 남기고 29초 만에
> 종료, 재시도는 빈 결과). 종합에서 제외했다.
>
> 종합: 오케스트레이터가 아래 §2 의 근거를 **모두 직접 열어 검증**했다.
> (이전 회차 종합본은 `.final-report-prev.md` 로 보관)

## 1. 결론 요약

**서버 권위 "상태" 동기화는 동작한다.** 좌표·방향·HP·MP·선점·킬 크레딧·전리품·사망 누계가
서버에서 판정되어 모든 구독자에게 간다. 세 AI 가 이 뼈대에는 이견이 없고, 실서버 통합 테스트
43 개가 뒷받침한다.

**요청하신 "여러 화면에 동일한 애니메이션·발사체 궤적·몹 공격 모션·피격 연출" 은 미구현이다.**
원인은 하나로 모인다 — **서버가 판정만 하고 그 사건을 상태로 남기지 않거나, 남긴 상태를
클라이언트가 연출로 바꾸지 않는다.**

그리고 **이 분석이 아니었으면 놓쳤을 결함**이 하나 나왔다. 직전 커밋(f2e1b14)에서 새로 만든
시간 기반 보간이 **실제 게임 경로에서는 매 프레임 리셋되어 옛 방식으로 퇴화한다.** 단위
테스트는 서버 갱신 시점에만 스냅샷을 넣어 이 경로를 재현하지 않았다. codex 단독 지적이며,
직접 열어 확인한 결과 사실이다.

## 4. 왜 이렇게 되었나 — 원인은 하나다

이 게임은 사건을 **별도 이벤트 표가 아니라 상태 열의 값 변화**로 전달한다
(`world.rs:393-425` 의 설계 주석, `GAME-SERVER.md:310-320` 의 insert-즉시-delete 함정 회피).
재구독에 강한 좋은 선택이다.

문제는 그 규칙을 **일부에만 적용**했다는 것이다.

| 사건 | 상태 열 | 클라 연출 |
|---|---|---|
| PC 공격 | `last_attack_at`·`attack_dir_*`·`attack_skill` | ✅ 있다 |
| PC 사망 | `deaths` | ✅ 있다 |
| PC 피격 | `last_damaged_at` **있다** | ❌ 없다 — 열을 안 읽는다 |
| 몹 사망 | `alive` **있다** | ❌ 없다 — 전이를 안 본다 |
| 몹 공격 | ❌ 없다 | ❌ 없다 |
| 발사체 | ❌ 없다 | 발사자 화면에만 |

여섯 중 둘만 완성돼 있고, 둘은 **열이 이미 있는데 클라이언트가 안 쓰며**, 둘은 열 자체가
없다. 이 표가 곧 작업 순서다.

## 5. 리스크 · 함정

- **보간 리셋 수정은 조건을 잘못 걸면 반대로 멈춘다.** "좌표가 같으면 구간을 안 연다"로 고쳐야
  하는데, 부동소수 비교를 엄격히 하면 미세한 값 변화마다 리셋이 남는다.
- **HP 감소 감지는 회복과 리스폰을 걸러야 한다.** `regen_tick` 과 사망 재가동의 HP 리셋을
  피격으로 오인하면 안전지대에서 계속 맞는 연출이 난다(kimi 지적).
- **몹 사망 시 엔티티를 즉시 지우면 리스폰과 충돌한다.** 같은 id 가 20 초 뒤 `alive:true` 로
  살아나고, 현재 스트리밍은 같은 엔티티를 재사용한다(`action_rpg_game.dart:1272-1285`).
- **몹 공격 열을 추가하면 재배포가 필요하다.** 열 순서 규칙(맨 끝·기본값)을 지켜야 하고,
  직전에 겪은 "배포된 순서와 어긋나면 마이그레이션 거부"를 다시 밟을 수 있다.
- **원격 발사체에 판정을 넣으면 안 된다.** `isServerJudged` 를 반드시 켜야 이중 피해가 안 난다.
- **문서가 코드보다 뒤처져 있다.** `GAME-DESIGN.md §13` 과 `.cowork/cowork-prompt.md` 는
  "멀티 동기화 없음·HP 120·몹 레벨 없음"이라 적고 있으나 전부 이미 구현돼 있다. 세 AI 가
  모두 지적했다.

## 6. 반증된 주장 — 이것으로 고치지 말 것

- ❌ **"몹 피격 연출이 전무하다"**(grok 1차) — `_hitFlash` 가 있다. grok 이 스스로 철회했다.
- ❌ **"피격 연출에 새 `last_hit` 열이 필요하다"**(grok 1차) — `last_damaged_at` 이 이미 있다.
- ❌ **"서버 몹이 안 죽는다"** — `isAlive` 는 false 가 되어 타겟팅에서 빠진다
  (`enemy.dart:180`). 실제 증상은 **시체가 서 있고 폭발·점수가 없는 것**이다.
- ⏸ **"public 표를 private + projection view 로"**(codex 8) — 요청 범위 밖이고 AoI 성능이
  미검증이다. 보류.
- ⏸ **"이동을 완전한 서버 시뮬로"**(codex) — `GAME-SERVER.md` 가 속도 캡 방식을 의도했다.
  설계 변경이므로 별도 판단이 필요하다.

## 7. 최종 권고 〔작업 지시서〕

**A. 서버 변경 없이 되는 것 — 먼저 한다**

| 순위 | 무엇 | 어디 |
|---|---|---|
| 1 | **보간 구간 리셋 수정** — 서버 좌표가 실제로 바뀌었을 때만 새 구간을 연다 | `remote_player.dart`·`enemy.dart` |

| 4 | **서버 XP·레벨을 화면에** — 서버가 올린 성장을 HUD 에 반영 | `action_rpg_game.dart` |
| 5 | **원격 스킬 발사체** — `attack_skill == plasma` 면 관찰자도 볼트를 본다(판정 없음) | `remote_player.dart` |
| 6 | **PK 입력 배선** — 근접 후보에 다른 요원 포함, `attackPlayer` 호출 | `action_rpg_game.dart` |

**B. 서버 변경이 필요한 것**

| 순위 | 무엇 | 어디 |
|---|---|---|
| 7 | **몹 공격 사건** — `Monster` 에 `last_attack_at`·공격 방향을 맨 끝에 추가하고 `monster_ai` 가 때릴 때 기록. 클라는 전이를 보고 타격 모션 | `world.rs` + `enemy.dart` |

- 킬 피드(`monster_kill` 구독) — 기능 추가이지 결함이 아니다.

## 8. 불확실

- claude 분석이 빠졌다. 나머지 셋이 서로를 충분히 교차 검증했고 결론을 좌우한 근거는 모두
  직접 확인했으므로, 이 누락이 §7 을 바꾸지는 않는다고 본다.
- 몹 공격 사건 열 추가의 실제 대역폭 증가는 측정하지 않았다. 어그로 중인 몹만 갱신되므로
  미미할 것으로 보이나 [추측]이다.
- 지연이 있는 실제 네트워크에서 "동일한 애니메이션"은 같은 서버 사건·같은 결과의 재생을
  뜻하지, 같은 벽시계 프레임의 동시 재생을 뜻할 수 없다. 후자는 보장할 수 없다.

## 9. 적용 결과

§7 의 권고를 **1~8 전부 적용**했다. §1~8 은 수정 전 사실의 기록이므로 그대로 둔다.

### 적용한 것

| 권고 | 무엇을 했나 | 파일 |
|---|---|---|
| 1 | `_beginSegment` 가 **좌표가 실제로 바뀌었을 때만** 새 구간을 연다. 게임 루프가 매 프레임 스냅샷을 밀어 넣어도 진행도가 리셋되지 않는다 | `remote_player.dart`·`enemy.dart` |
| 2 | `alive true→false` 전이에서 `_die()` — 폭발·점수·화면 제거. 아직 월드에 붙지 않은 몸은 `isMounted` 로 걸러 연출을 건너뛴다 | `enemy.dart` |
| 3 | `last_damaged_at` 을 `MyWorldState` 에 노출하고, 그 시각이 바뀌면 `playHurtReaction` — 데미지 숫자·화면 흔들림·피격음 | `world_presence.dart`·`spacetime_world_presence.dart`·`player.dart`·`action_rpg_game.dart` |
| 4 | `serverTotalXp` 를 노출하고, 서버 쪽이 앞설 때만 그 차이를 `gainXp` 로 채운다(레벨업 연출 포함) | 같은 세 파일 |
| 5 | 원격 요원이 `attack_skill == plasma` 를 받으면 **피해 0 짜리** 볼트를 띄운다 | `remote_player.dart` |
| 6 | 근접 스윙이 부채꼴 안의 다른 요원을 찾아 `attackPlayer` 로 **의도만** 보낸다. 로컬에서 HP 를 깎지 않는다 | `action_rpg_game.dart`·`player.dart` |
| 7 | `Monster.last_attack_at` 을 맨 끝에 추가하고 `monster_ai` 가 **실제로 때린 틱에만** 기록. 클라는 전이를 보고 `EnemyPhase.strike` 를 0.28 초 재생 | `world.rs`·`enemy.dart`·`action_rpg_game.dart` |
| 8 | `award_kill` 의 레벨 갱신에 `max_mp`/`mp` 추가 | `world.rs` |

### 적용하며 새로 찾은 것

- **`isMounted` 방어가 필요했다.** 권고 2 를 넣자 기존 테스트가 깨졌다 — 게임 트리에 붙기 전
  사망 스냅샷이 오면 폭발을 낼 곳이 없어 그 자리에서 죽는다. 스트리밍이 몸을 만든 직후
  첫 스냅샷을 넣는 순간이 실제로 그 경로다.
- **회귀 테스트의 지표가 틀렸다.** 권고 1 을 고친 뒤 "매 프레임 리셋" 을 재현하는 테스트를
  넣었는데, 가드를 없애도 통과했다. 멈춘 프레임 수를 세는 지표로는 지수 감쇠를 잡을 수 없다 —
  그 방식은 아예 서는 것이 아니라 **갱신 주기마다 빨라졌다 느려지기** 때문이다. 프레임별
  이동거리의 변동계수로 바꾸자 가드 없이 0.246(문턱 0.2)으로 잡혔다.
- **통합 테스트끼리 같은 몹을 두고 경쟁했다.** 병렬 실행에서 모두 "안전지대 밖 가장 가까운
  몹" 을 고르다 한쪽이 잡아 버린 몹을 다른 쪽이 기다리며 실패했다. 파일마다 사냥 구역을
  남/북으로 갈랐다. 기능 결함이 아니라 테스트 설계 문제였다.

## 10. 후속 — "몬스터가 투명해 보인다"

§9 적용 뒤 제기된 증상이다. 함께 제시된 가설은 이랬다:

> PC 가 멈추고 몹이 붙어 있으면 → 몹이 안 움직여 DB 가 갱신되지 않고 → 구독 이벤트가
> 오지 않아 → 화면에 몹이 나타나지 않는다.

**전반부는 사실, 후반부는 사실이 아니다.** 실측으로 갈랐다.

### 실측 1 — 멈춘 몹의 행은 사라지지 않는다

`test/idle_monster_visibility_test.dart` 를 만들어 실서버에서 쟀다. 몹에게 1.5 타일까지
붙어 선 뒤 **아무것도 하지 않고** 30 초를 지켜봤다.

```
감시 시작 — 몹 #18972 at (389.4, 503.7), 주변 몹 237 기
 5초: 전체 237 기 · 살아있음=true 좌표변화 0 회
30초: 전체 237 기 · 살아있음=true 좌표변화 0 회
```

몹은 **한 번도 움직이지 않았지만**(가설 전반부 확인 — `monster_ai` 는 사거리 안에서
`step_toward` 를 아예 거치지 않는다) **행은 캐시에 그대로 남았다.** SpacetimeDB 구독은
초기 스냅샷으로 캐시를 채우고, 갱신이 없어도 행이 지워지지 않는다. 따라서 "이벤트가
없어서 사라진다"는 성립하지 않는다.

서버 AI 도 정상이었다. 로그의 이동 기수 분포를 보면 0~7 기가 고르게 나온다 — 관측 순간의
"0 기 이동" 은 어그로 안의 몹이 이미 다 붙어 있었기 때문이다.

### 실측 2 — 진짜 원인은 표시 상한이었다

몹 좌표를 받아 밀도를 쟀다. 가장 조밀한 저레벨 사냥터 기준:

| 반경 | 몹 수 (레벨 1~5 만) |
|---|---|
| 15 타일 | 37 기 |
| **22 타일 (화면 반폭)** | **66 기** |
| 30 타일 | 89 기 |
| 60 타일 (당시 스트리밍 반경) | 122 기 |

표시 상한은 **50** 이었다. 즉 **화면 안에 있어야 할 66 기 중 열여섯 기가 그려지지
않았다.** 게다가 스트리밍 반경 60 은 화면 반폭의 세 배에 가까워, **눈에 보이지도 않는
몹이 상한을 먼저 채웠다.** 어떤 몹은 보이고 어떤 몹은 안 보이니 화면이 성기게 비어
보인다 — "투명하다" 로 읽힌 증상이다.

### 고친 것

- `_monsterReleaseRadius` 60 → **34**. 화면 반폭 + 여유. 보이지도 않는 몹이 상한을
  먹지 않는다.
- `_maxActiveMonsters` 50 → **120**. 실측된 화면 안 밀도(66 기)를 여유 있게 덮는다.
- 정렬을 **화면 안 우선 → 거리순**으로 바꿨다. 아이소메트릭에서는 화면 모서리 밖의 몹이
  화면 한복판의 몹보다 가까울 수 있어, 거리만으로 자르면 정작 보여야 할 자리가 빈다.
